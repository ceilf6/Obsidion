## 零、名词解释

| 名词 | 描述 | 示例 |
| --- | --- | --- |
| SPU | 标准产品单元，聚合了属性值、特性相同的商品属性值、特性相同的商品聚合起来，就形成了 SPU，每个 SPU 至少包含一个 SKU。示例中的拿铁商品，共有 18 个 SKU（3 种杯型 * 6 种温度） |  |
| SKU | SKU 是物理上不可分割的库存单元，也是点餐领域实际售卖的商品。例如大杯/热拿铁是一个 SKU ，中杯/热拿铁也是一个 SKU备注：若无规格互斥规则，所有的售卖属性组的笛卡尔积都和一个SKU一一对应。以上述 【杯型: 中杯、大杯】【温度: 冰、热】为例中杯-冰 中杯-热 大杯-冰 大杯-热都需要在商品下挂的SKU列表中 |  |
| 售卖属性 | 组成 SKU 的基本属性，无价格，不支持售卖。示例中【杯型】和【温度】是规格组，不同规格组中的规格进行交叉组合，可形成不同的 SKU，如下图所示特殊情况：部分商品可能无属性组，商品本身就是单SKU。 |  |
| 配料 | 商品的可选配料，有价格，不可单独售卖。示例中【添加或更换牛奶】、【奶泡】都是配料组，里面的「全脂牛奶」等都是配料 |  |
| 直连套餐 | 区域于单品的独立商品类型，本身可独立售卖，常见于西快的汉堡套餐，瑞幸也有使用。 |  |
| M选N | 一张团购券关联了M个商品，用户只能选择其中N份（部分可重复选，部分不可以）。如10选1、15选2。常规情况下都是1个团购关联一个分组，1个分组有多个商品；这里就引出多分组的概念，是指存在1个团购关联多个分组，每个分组下多个商品，类似M选N多分组、固定套餐品。 | 单分组： 多分组： |
| 秒提品 | 秒提商品，区别于团购品，在线点货架展示的商品除营销套餐外都是秒提品。 |  |
| 囤点提单/可囤可点 | 当前重点迭代链路，在货架拉起点单tab，也可以切到囤券tab，是可囤可点的二合一页面。 |  |
| 融合货架 | 在 POI 页的货架，融合了团购货架和在线点货架并支持即买即点的能力。 |  |

## 一、业务简介

### 1.1 业务定位

商品选规格页作为囤点交易链路的核心页面（导购浏览->**选品选规格**->交易下单->履约售后），UV日均 180W+()。当前已支持茶咖()、西快()、零售()等多品类的商品选购及定制能力诉求（如单品定制、M选1选购、直连套餐选购等）。同时商品规格定制作为必要且高频迭代模块，通过不同的来源判断以组件、页面级形式支持囤点选规格、团购券核销、购物车修改规格等场景复用。当前主要覆盖美团及点评共4端。核心复杂逻辑在其客制化规则（如售卖属性互斥、客制化属性合法校验等）。

### 1.3 关注哪些指标

业务指标是产、研、运三方共同最为关注的指标，任何的功能开发、技术优化都会在业务指标中体现，所以需要保证对业务指标的正确理解。

### 5.2 售卖属性互斥及客制化逻辑

### **5.2.1 售卖属性互斥**

主要场景是解决某些SKU售罄则不可选中特定组合的属性值。[互斥算法](https://km.sankuai.com/collabpage/2324091209)核心就以下2点：

1. 
    - **生成缺失 SKU 集合**：售卖属性笛卡尔积 - 现有可用 SKU = 缺失 SKU 集合 C
2. 
    - **动态禁用计算**：用户每次选择属性后，用「已选的 n-1 组合」()去匹配集合 C，找到需要禁用的属性。
    当前存在的问题：**禁用算法效率较低，有局限性（如单一属性对应的SKU都不存在，并不能一开始禁用掉）**
