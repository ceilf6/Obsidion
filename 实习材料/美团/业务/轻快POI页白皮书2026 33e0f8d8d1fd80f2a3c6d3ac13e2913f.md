### 1.1 业务定位

POI页是美食团购业务的重要入口，是囤点交易链路的核心页面（**导购浏览**->选品选规格->交易下单->履约售后），当前轻快餐POI日均UV550w+，约占整体POI流量的22%()。轻快餐货架()已经覆盖了大部分茶咖、西快、零售等品类品牌，轻快餐POI页旨在提供流畅、准确的用户体验，以吸引更多的用户进行选品、下单。

### 路由参数在业务中的主要应用场景

### *1. ** **topProducts 已购券高亮**

**作用**：从外部带参数进 POI 时，在「用户已购券」横滑列表里置顶一张券并高亮。
- **入参**：pageParam.topProducts，JSON 字符串，例如：[{ "pid": "目标 dealId" }]。
- **逻辑**：在 usePurchasedDeal 里用 topProducts[0].pid 和已购券列表的 [item.id](http://item.id/) 做匹配，匹配到的那张券记为 highlightProductListMatchItem。
- **表现**：该券卡片外会套一层 **HighLightBorder**（高亮边框）：淡入 → 保持约 6 秒 → 淡出，然后通过 closeHighLight 关掉高亮。

### **2. 搜索 / 猜你喜欢：货架商品高亮 + 锚点置顶**

**作用**：从搜索/猜你喜欢进 POI 时，把对应套餐滚动到视野内并做高亮动效。
- **入参**：
- searchDealId：要定位并高亮的 dealId
- topFlagType === '1'：需要做「置顶/锚点」到轻餐货架
- isDealHighlighted === '1'：需要做高亮动效
- **来源**：source 为 meishi_search_deal、mt_search_deal、guess，或仅用 topFlagType + isDealHighlighted。
- **逻辑**：
- **HighlightStore**：当 shouldDoAnimate 为 true 且当前商品 dealId === searchDealId 时，对该商品做边框、箭头、文案的高亮动画（ColorBorder / ColorArrow / ColorText）。
- **sectionHeader**：当 topFlagType === '1' 时，会触发 scrollToTabber，把轻餐货架滚到顶部（锚点置顶）。

### **商品卡片（SnackItem）的“定高”规则**

### **1. 版本选择（AB 实验）**

```
- **小图**（非 AB）：用 getSnackItemHeight → 110 / 128 两档。
- **大图**（AB）：用 getSnackItemHeightLargeImageVersion → 129 / 147 两档。
```

### **2. 小图版 getSnackItemHeight(itemData)**

```
- 默认：**110px**（NEW_SNACK_ITEM_HEIGHT）。
- 若存在 **促销标签**（promotionTag.shortTag / priceTag）或 **低价/x 件 y 折标签**（dealLowPriceTagList 有内容） 或 **库存及倒计时**信息（!!itemData?.stockInfo || !!itemData?.countDownEndTime） → 用 **128px**（PROMOTION_SNACK_ITEM_HEIGHT）。
```

### **3. 大图版 getSnackItemHeightLargeImageVersion(itemData)**

```
- 默认：**129px**（LARGE_IMAGE_SNACK_ITEM_HEIGHT）。
- 若 **有促销/低价** 且 **有副标题**（subTitle.icon 或 subTitle.text）→ 用 **147px**（LARGE_IMAGE_PROMOTION_SNACK_ITEM_HEIGHT）。
```

### **4. 特殊展示（不参与动态高度）**

```
- lessParam === true（如营销区大图）或 showType === 'notAvailableForBuy'：直接用对应版本的“默认高度”（小图 110 / 大图 129），不再按促销/副标题细分。
```

### **5. 动态修正与写回 Store**

```
- 初始：优先用 shelfStore.getSnackHeightById(snackId)，没有则用上面规则算出的 finalSnackHeight。
- 标题行数变化时 onLinesChange：
- 需要“有促销那档”时用 finalPromotionSnackItemHeight（128 或 147）；
- 否则用 finalSnackItemHeight（110 或 129）；
- 算完后 **写回** shelfStore.setSnackHeightById(snackId, height)，供列表算 offset。
```
