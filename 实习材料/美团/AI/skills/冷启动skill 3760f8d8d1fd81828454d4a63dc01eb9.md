# 冷启动skill

Source: [KM 2766732240](https://km.sankuai.com/collabpage/2766732240)

根据我对这个工作区的分析，"冷启动 SKILL"指的是一种**为新项目从零建立测试体系提供完整脚手架和规范指引的 Skill**。

具体来说，以 `fe-3-layer-testing-migration` 这个 Skill 为例，它的"冷启动"含义是：当一个业务仓库**尚未建立测试体系**（没有测试目录结构、没有测试配置、没有测试规范文档）时，AI Agent 可以通过调用这个 Skill，一次性完成以下工作：

**一键生成完整测试基础设施**：包括三层测试目录结构（layer1 业务语义 → layer2 可执行任务 → layer3 测试代码）、测试配置文件、追溯报告脚本、失败分诊脚本、命令入口文档等。本质上是把一个"测试空白"的仓库，快速拉到"测试体系就绪"的状态。

**为什么叫"冷启动"**：类比引擎冷启动——项目在测试维度是"冷"的（零基础），这个 Skill 提供了从 0 到 1 的全套模板、脚手架脚本和规范约束，让 Agent 能在无人工预配置的情况下，自动完成测试体系的初始化搭建。

**与普通 Skill 的区别**：普通 Skill 通常假设项目已有一定基础设施，在此之上做增量操作（比如写测试用例、修 bug）。冷启动 Skill 则专门解决"从无到有"的问题——它内置了完整的模板资产（`assets/templates/`）、脚手架脚本（`scripts/scaffold-testing-system.js`）和架构参考文档（`references/testing-architecture.md`），确保即使目标仓库完全没有测试相关内容，也能一步到位地建立起规范化的测试体系。

你提到的"后续将在更多业务仓库中验证通用性"，就是要验证这套冷启动方案能否适配不同的目录结构、测试框架配置和 nativeMCP 接入方式，从而成为一个可复用的标准化测试体系初始化工具。
