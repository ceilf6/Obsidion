# 无标题

方案: https://km.sankuai.com/page/143886652#id-2.1.7Git%E8%A7%84%E8%8C%83
特点: 到店平台的前端工作流程规范
解决因为终端内灰度发布流程推广，带来的分支模型复杂度提升，以及可能造成的线上问题。
• hotfix风险：hotfix 带上灰度代码到 master，目前是master分支不允许发灰度，参考预发布分支。
• 并行灰度分支之间覆盖：feature分支交付速度不一致特性带来的，灰度发版分支和时机问题。
解决历史线上故障中，因为分支模型缺失导致的线上问题
分支模型: 主分支：master
测试 / 预发布 / 开发集成分支
功能分支：feature/mis-yyyymmdd/{id}(可选)/{简要描述} 
缺陷修复分支：bugfix/mis-yyyymmdd/{id}(可选)/{简要描述} 
灰度/发版分支：release/mis-yyyymmdd
发布重建：使用hotfix分支命名

2.1.7.2 分支规范强制
分支命名规范（task id 可以为 Ones，Flow 等其他需求提报平台），可使用 `npx git newbranch` 辅助新建分支，并会在本地 gitHooks#pre-push 阶段校验
• 主分支：master
• 测试 / 预发布 / 开发集成分支更新强制：正式灰度/上线前需要在测试环境进行预发布，检测冲突提前暴露问题。
    ◦ test 测试分支：test/(**)，功能分支合并测试，借助code lightemerge 工具集成测试。
        ▪ test 公共分支
        ▪ test/@{包名}(可选)/#{其他用途}(可选)/{id}(可选)/{简要描述}： 分组测试分支。
    ◦ 规范不再约束 staging/lightmerge/develop/beta：业务可以按自身需求使用，此处不限制这些分支的使用。
• 功能分支：feature/mis-yyyymmdd/{id}(可选)/{简要描述} （例：feature/mis-20200730s/poi-filter）。
    ◦ 泳道分支新增推荐：(feature/hotfix/bugfix)/mis-yyyymmdd/{sl-泳道信息}(可选)/{id}(可选)/{简要描述}（例：feature/mis-20200730/sl-1938-xxxxx/km-1234/auto-commit-msg-scope-pkgName），支持CD功能。
    ◦ 包分支新增推荐：(feature/hotfix/bugfix)/ mis-yyyymmdd / @{包名}(可选)/{id}(可选)/{简要描述}（例：feature/mis-20200730/sl-1938-xxxxx/@product-tongzhou/km-1234/auto-commit-msg-scope-pkgName），支持CD功能。
    ◦ 注：id 关联 km-xx(学城 id)，ones-xx（缺陷/需求 ones id）， tt-xx（TT id）；泳道信息以 sl-xxx前缀（方便解析）,包名以@为前缀。
    ◦ 完整版： (feature/hotfix/bugfix))/ mis-yyyymmdd/{sl-泳道信息}(可选) /@{包名}(可选)/#{其他用途}(可选)/{id}(可选)/{简要描述}，⚠️注意顺序固定。#为保留功能。
• 缺陷修复分支：bugfix/mis-yyyymmdd/{id}(可选)/{简要描述} （例：bugfix/mis-20200730/uploader）
• 紧急修复分支：hotfix/mis-yyyymmdd/{id}(可选)/{简要描述}（例：hotfix/mis-20200730/search-input）
• 灰度/发版分支新增强制：release/mis-yyyymmdd/@{包名}(可选)/{id}(可选)/{简要描述}(例： release/mis-yyyymmdd/search-input)，如使用灰度强制该规范。
    ◦ 常驻分支：release
• 发布重建（回滚场景https://km.sankuai.com/page/405292315）：使用hotfix分支命名。master 通过git revert 进行版本回退，重新merge 或cherry pick 特性分支，禁止使用git reset 与 git push --force。
