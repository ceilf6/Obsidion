组件和物料是同一个意思

> 
> 
> 
> 更接近的理解是：
> 
> 不是“每个组件都一定是一个包”，而是“这个页面由一组物料节点拼出来，其中 `proCode` 物料通常对应独立发布的 npm 包，`lowCode` 物料则更像平台里的低代码物料/配置化节点”。你这个仓库里就能看到这种区分，比如 [componentsMap.json](https://www.notion.so/Users/ceilf6/Desktop/duo-food-order-submit/componentsMap.json) 里同时有：
> 
> - `materialType: "proCode"` + `npm` + `npmVersion`，这类基本就是独立物料包
> - `materialType: "lowCode"` + `name`，这类不是当前仓库里的独立源码包形态
> 
> 另外，DUO 页面不只是“组件升级记录”。这个仓库里实际存了页面编排和运行配置本身，比如：
> 
> - 页面依赖和物料版本映射在 [componentsMap.json](https://www.notion.so/Users/ceilf6/Desktop/duo-food-order-submit/componentsMap.json)、[dependencies.json](https://www.notion.so/Users/ceilf6/Desktop/duo-food-order-submit/dependencies.json)
> - 页面结构编排在 [struct.groovy](https://www.notion.so/Users/ceilf6/Desktop/duo-food-order-submit/struct.groovy)
> - 数据源入参/出参映射在 [dataSourceMap.groovy](https://www.notion.so/Users/ceilf6/Desktop/duo-food-order-submit/dataSourceMap.groovy)
> - 页面级构建配置在 [pageBuildConfig.json](https://www.notion.so/Users/ceilf6/Desktop/duo-food-order-submit/pageBuildConfig.json)
> 
> 所以更准确地说：
> 
> 1. 页面是由很多 DUO 物料节点组装出来的。
> 2. 其中一部分物料节点确实对应独立包，并通过版本号引用。
> 3. 当前页面仓库主要保存“页面装配关系 + DSL 配置 + 依赖版本”，不是只保存 commit 信息。
> 4. Git 提交历史里“升级组件/升级版本”很多，说明它经常通过改依赖版本来升级页面；但历史里也有大量 `struct.groovy`、`dataSourceMap.groovy` 的业务改动，所以不只是包更新记录。
