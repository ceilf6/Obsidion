# 分支流程

1. 基于 FEDO 的分支流是怎样的？
    
    FEDO 基于[前端标准化](https://km.sankuai.com/page/143886652)规范，默认整合了标准化分支流程：
    
    1. 开发时创建 feature 分支，完成开发、测试、验收过程中的迭代；
    2. 开发完成的 feature 分支向 release 分支发起 PR，完成 code review 后合并至 release/xx；
    3. （待线上化）灰度的 release/xx 分支在灰度验收环节需要修复时，通过 release/xx 切出 bugfix 分支或直接在 feature 分支（此时 release 分支未集成其他 feature 代码）完成修复重提 PR，合并后执行灰度热更新验证；
    4. 灰度期间存在线上环境变化时，由 release/xx 同步 master 分支执行热更新；
    5. 灰度结束后，将 release 分支合并至 master 分支；
2. release 分支同步 master 分支时存在冲突怎么办？
    
    release 分支同步 master 冲突时，复用当前 feature 分支同步最新代码解冲突，完成后通过 PR 合入 release 分支
