# 环境变量

Source: [KM 2761180475](https://km.sankuai.com/collabpage/2761180475)

## 问题

### Context

ones-dashboard 后端聚合了 ONES、DevTools Code、MDO、catKey/DAM、Raptor 五个数据源。当前运行时出现 5 个明确的错误，导致部分字段无法获取真实数据。经过分析，这 5 个错误分为两类：**环境配置缺失**（3 个）和**代码 bug + 策略改进**（2 个）。

---

### 错误 1：DevTools Code 鉴权缺失

**错误**: `未配置 DevTools Code 鉴权，已跳过 CR/PR 数据。请设置 DEVTOOLS_CODE_BASIC_AUTH 或 DEVTOOLS_CODE_COOKIE。`

**根因**: `devtoolsCode.ts:205-223` 检查 `DEVTOOLS_CODE_BASIC_AUTH` 或 `DEVTOOLS_CODE_COOKIE` 环境变量，两者均未配置。

**方案**: 纯配置问题，无需改代码。在 `.env` 中配置其中一个即可。同时注意到项目已有 `devtoolsCodeAuth.ts`（520 行，支持 3 级鉴权解析：显式 token → 外部命令 → SDK），但当前 dashboard 流程未使用该模块。**暂不集成**，避免引入不必要的复杂度。

**行动**:

- [ ]  确认用户有 DevTools Code 的 Cookie 或 Basic Auth 凭据
- [ ]  在 `.env` 中配置 `DEVTOOLS_CODE_BASIC_AUTH` 或 `DEVTOOLS_CODE_COOKIE`

---

### 错误 2：MDO Bearer Token 缺失

**错误**: `未配置 MDO_AUTH_BEARER，已跳过 MDO 数据。`

**根因**: `mdo.ts:30` 检查 `MDO_AUTH_BEARER` 环境变量，未配置。

**方案**: 纯配置问题。MDO 平台使用 httpOnly Cookie，无公开 REST API 文档，只能通过浏览器登录态获取 Bearer Token。

**行动**:

- [ ]  确认用户能获取 MDO 的 Bearer Token
- [ ]  在 `.env` 中配置 `MDO_AUTH_BEARER`

---

### 错误 3：ONES 服务项查询失败（browse.git）

**错误**: `ONES 服务项查询失败，repo=ssh://git@git.sankuai.com/ka-brand-platform/browse.git`

**根因**: `catkey.ts:132-155` 调用 `GET {ONES_BASE_URL}/api/1.0/ones/projects/apps/getProjectWithAppByRepo?repo={encoded(repo)}` 返回 null。

**两个可能原因**:

1. **代码 bug** — `common/src/ones/index.ts:94` 使用了 `decodeURIComponent(repo)` 而非 `encodeURIComponent(repo)`。对于包含特殊字符的 repo URL，`decodeURIComponent` 会导致 URL 参数损坏，API 返回空结果。**但**这个函数在 `common` 包里，dashboard 的 `catkey.ts` 有自己独立的 `queryProjectApps()` 实现（使用了正确的 `encodeURIComponent`），所以这个 bug 不影响 dashboard 流程。
2. **repo 未在 ONES 注册** — `ssh://git@git.sankuai.com/ka-brand-platform/browse.git` 这个仓库可能没有在 ONES 项目中关联服务项，API 确实返回空。这是数据缺失问题，非代码问题。

**行动**:

- [ ]  **修复 bug**: 修正 `common/src/ones/index.ts:94` 的 `decodeURIComponent` → `encodeURIComponent`（虽然不影响 dashboard，但影响其他调用方）
- [ ]  **增加日志**: 在 `catkey.ts:146-148` 的 `!response.ok` 分支和 `catch` 分支中，将失败的 HTTP 状态码或异常信息写入 warning（当前仅提示"查询失败"但无具体原因）
- [ ]  **确认数据**: 需要确认 `ka-brand-platform/browse` 这个仓库是否在 ONES 中有对应的服务项

---

### 错误 4：DAM 凭据缺失

**错误**: `未配置 DAM_CLIENT_ID / DAM_CLIENT_SECRET，无法执行 catKey 回退查询。`

**根因**: `catkey.ts:158-167` 检查 `DAM_CLIENT_ID` 和 `DAM_CLIENT_SECRET` 环境变量，均未配置。DAM 是 catKey 解析的回退链路（ONES 查询失败后的 fallback）。

**方案**: 纯配置问题，需要 DAM 平台的 HMAC 签名凭据。

**行动**:

- [ ]  确认用户能获取 DAM 的 `DAM_CLIENT_ID` / `DAM_CLIENT_SECRET`
- [ ]  在 `.env` 中配置这两个变量

---

### 错误 5：catKey 解析失败（级联失败）

**错误**: `未从 ONES 服务项或 DAM 回退链路中解析到有效的 catKey。`

**根因**: 这是错误 3 + 错误 4 的级联结果。catKey 解析的链路是：

1. ONES `queryProjectApps` → 失败（错误 3）
2. DAM `GET /api/v1/projects/catkey?git=<repo>` → 跳过（错误 4，无凭据）
3. 无 catKey → Raptor 监控数据也无法获取

**方案**: 修复错误 3 和 4 后，此错误自然消失。但可以增加一个**第三级 fallback**：从 repo 名称推断 catKey（部分仓库的 catKey 命名与 repo slug 一致）。

**行动**:

- [ ]  确认错误 3 和 4 解决后此错误是否消失
- [ ]  （可选）在 `catkey.ts` 中增加基于 repo slug 的启发式 fallback

### 修改 2：修复 `common/src/ones/index.ts` 的 URL 编码 bug

**文件**: `packages/common/src/ones/index.ts:94`

```
// 代码块
- `/api/1.0/ones/projects/apps/getProjectWithAppByRepo?repo=${decodeURIComponent(repo)}`
+ `/api/1.0/ones/projects/apps/getProjectWithAppByRepo?repo=${encodeURIComponent(repo)}`
```

**原因**: `decodeURIComponent` 会将已编码的 URL 组件解码，对于包含 `/`、`:` 等字符的 repo URL 会导致参数损坏。wenger 的 `queryProjectApps` 也存在同样的 bug。虽然 dashboard 的 `catkey.ts` 有独立实现已使用正确的 `encodeURIComponent`，但 `common` 包的其他调用方会受影响。

### 修改 3：改进 catKey 查询的错误日志

**文件**: `packages/backend/src/services/catkey.ts`

在 `queryProjectApps()` 函数（line 132-155）中增加更详细的错误信息：

```
// 代码块
// line 146-148, 当前：
if (!response.ok) {
  return null;
}

// 改为：
if (!response.ok) {
  return { __error: `HTTP ${response.status}` };
}
```

并在调用方（line 42-47）处理这个错误信息，将 HTTP 状态码写入 warning：

```
// 代码块
const apps = await queryProjectApps(repo);
if (!apps) {
  hadLookupError = true;
  warnings.push(`ONES 服务项查询失败，repo=${repo}`);
  continue;
}
if (apps.__error) {
  hadLookupError = true;
  warnings.push(`ONES 服务项查询失败，repo=${repo}，${apps.__error}`);
  continue;
}
```

**原因**: 当前仅提示"查询失败"，无法区分是网络异常、401 鉴权失败、404 接口不存在还是 API 返回空数据。

### 修改 4（可选）：Raptor 走 query param 而非 env var

**当前**: `raptor.ts` 从 `RAPTOR_TOKEN` 环境变量读取 token，分别注入 V1 query param 和 V2 Authorization header

**wenger 实现**: token 同时作为 query param (`?token=`) 和 Authorization header

两个实现一致，`.env` 中配置 `RAPTOR_TOKEN` 即可，**无需改代码**。
