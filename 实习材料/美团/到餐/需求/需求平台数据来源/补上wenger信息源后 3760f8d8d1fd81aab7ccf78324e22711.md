## ONES Dashboard 接口补全计划

### Summary

- 保留现有 `/api/requirements` 和 `/api/requirements/:id` 两个接口，改成真实多源聚合：`ONES` 作为主数据源，`DevTools Code` 走旧 REST，`MDO` 走已验证的 REST，`Raptor/CAT` 提供真实 `pv` 和监控指标。
- 这版按“部分返回”落地：任何外部源失败都不打断页面，已拿到的数据照常返回，缺口通过可选 `warnings` / `sources` 明确标注。
- `mc/mv` 不造假；收益区改为 `pv` 真值 + `custom` 监控项展示。`Ocean` 本轮不接数值接口，只保留为后续元数据补充来源。

### Key Changes

- 后端聚合边界：
    - 列表接口只做 `ONES + branch + DevTools Code`，不在列表里接 `MDO/Raptor`，避免 N+1 放大。
    - 详情接口接完整链路：`ONES issue + branches + records + associates`、`DevTools PR/activities`、`MDO detail/problem`、`catKey/projectName` 解析、`Raptor/CAT` 监控数据。
- DevTools Code：
    - 放弃当前 OpenAPI/appkey 依赖，改为 `https://dev.sankuai.com/rest/api` 旧 REST。
    - 鉴权固定为环境变量模式：优先 `DEVTOOLS_CODE_BASIC_AUTH`，次选 `DEVTOOLS_CODE_COOKIE`；两者都没有则 `sources.code=unavailable` 并写 warning。
    - 继续产出 `crOpenCount`、`prUrl`、`crMembers`、`crItems`、`crStatusDistribution`。
- MDO：
    - 新增独立服务，接 `/api/v1/mdo/mdo/requirement/detail/full?key=` 和 `/problem?key=`。
    - 认证固定为 `MDO_AUTH_BEARER`；失败时不报整页错，只回 warning。
    - 详情响应新增 `mdo` 字段：`state`、`reqName`、`hasRisk`、`unresolvedProblemCount`、`deliveryLeadTime`、`link`。
- Raptor/CAT：
    - 新增 `catKey` 解析链路：先按 branch/repo 调 `queryProjectApps(repo)` 取 app 信息；如果没有 `catKey`，再用 `DAM` 的 `git -> catKey` 查询兜底。
    - `DAM` 调用按 `wenger` 的签名方式实现，但凭证改为环境变量：`DAM_CLIENT_ID`、`DAM_CLIENT_SECRET`。
    - `Raptor` 固定用 live API：`pv/distribution`、`log/simpleSummary`、`frontendApi performance`；令牌改为 `RAPTOR_TOKEN` 环境变量。
    - 详情 `benefit` 改成真实监控口径：
        - `metric="Raptor PV"`，`actual` 为总 PV，`trend` 为时间序列 PV。
        - `trackingMetrics` 填 `pv` 行；补充 `custom` 行：`jsErrorPv`、`jsErrorRate`、`firstScreenTP90`。
        - `indicators` 放数值型补充项：MDO 交付时长、未处理异常数等。
        - `mc/mv` 本轮不伪造，不返回假值。
- 响应与前端：
    - `RequirementListResponse`、`RequirementDetailResponse` 新增可选 `warnings: string[]`、`sources` 状态对象；详情新增 `mdo`。
    - 前端详情页新增 MDO 区块/字段展示 warning；收益面板支持 `expected<=0` 的真实监控模式，此时隐藏“达成率/人工校准”强依赖目标值的交互。
    - `trackingMetrics` 前端渲染从仅 `mc/mv/pv` 改为同时支持 `custom`，并对空 `mc/mv` 给出非阻断说明。
- 文档：
    - 收口 `field-api-mapping.md`，把 “MDO 只能 DOM”“Ocean 提供 mc/mv/pv 数值”“DevTools Code 依赖 appkey” 这些旧结论替换成这次确认后的真实链路。

### Public API / Types

- `RequirementDetailResponse` 新增：
    - `warnings?: string[]`
    - `sources?: Record<"ones" | "code" | "mdo" | "catkey" | "raptor", "ok" | "partial" | "unavailable">`
    - `mdo?: { state: string; reqName: string; hasRisk: boolean; unresolvedProblemCount: number; deliveryLeadTime?: number; link: string }`
- `RequirementListResponse` 新增可选 `warnings?` 与 `sources?`，其余字段保持兼容。
- `benefit.trackingMetrics` 继续复用现有结构，但允许 `type="custom"` 真正出现在 UI 中。

### Test Plan

- 服务层单测：
    - ONES 字段归一化、branch 解析、PR 状态统计、MDO problem 计数、catKey 解析链路、Raptor 响应转 `benefit`。
- 聚合接口测试：
    - 全部凭证存在时返回完整详情。
    - 缺 `DEVTOOLS`、缺 `MDO`、缺 `RAPTOR/DAM` 时接口仍成功，`warnings/sources` 正确。
    - 多 branch / 多 catKey / 无 branch / 无 PR / 无 MDO data 的详情返回正确。
- 前端验证：
    - 详情页能展示 `mdo`、`warnings`、`custom` tracking metrics。
    - `expected<=0` 时收益区不再显示误导性的达成率。
    - 列表页性能不因接入 MDO/Raptor 明显下降。
- 回归：
    - `pnpm --filter @nibfe/miaoti-exp-tools-backend` 的类型检查/启动 smoke。
    - `pnpm --filter @nibfe/miaoti-exp-tools-frontend build` smoke。
