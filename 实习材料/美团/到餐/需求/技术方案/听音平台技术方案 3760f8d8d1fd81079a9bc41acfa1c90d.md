## 初步构思

从端口获取数据之后，调用大模型进行数据的处理后再进行展示，问题的关键是如何处理从端口拿到的脏数据、以及如何构建提示词工程，二者配合去最大限度激发大模型处理问题 => PRD 的能力

所以技术方案的重点在于如何定义 schema 实现数据的转换与展示

目前我初步拟定如下

### 清洗层

将 TT 原始数据 HTML 进行标准化，抽取门店/项目/反馈内容/诉求/解决方案、统一时间和状态字段

拟定

// 代码块

### 技术选型

正则处理

### 请求层

将 json 对象数据放入请求中向大模型请求，

### 提示词工程

中间进行提示词处理提高输出质量

- 单条 prompt 角色固定为“产品问题分析助手”，禁止输出泛化空话，必须按 schema 返回 JSON。
- 单条 prompt 重点要求模型识别：商户真实诉求、当前产品行为、期望行为、可产品化的问题定义、优化方向、验收关注点。
- 聚合 prompt 不再直接分析原始 TT，而是输入逐条 AiIssueInsight，聚合产品主题和机会点。
- prompt 中必须明确“不要复述 TT 原文，不要输出客服话术，不要生成完整 PRD，只输出 PRD 种子”。
- 每个 prompt 必须带 promptVersion，未来调优只改版本和模板，不动组件。

> **ℹ️ 信息：**
> 
> 
> 提示词工程是需要不断测试、反馈、优化的
> 

### 输出

要求输出格式

```
// 代码块
type AiIssueInsight = {
  ticketId: string;
  productTitle: string;
  merchantScenario: string;
  currentBehavior: string;
  expectedBehavior: string;
  rootCauseHypothesis: string;
  productOpportunity: string;
  priority: "P0" | "P1" | "P2" | "P3";
  confidence: "high" | "medium" | "low";
  evidence: string[];
  prdSeeds: {
    changePoints: string[];
    acceptancePoints: string[];
    metricSeeds: string[];
  };
};
```

将输出存储到仓库中
