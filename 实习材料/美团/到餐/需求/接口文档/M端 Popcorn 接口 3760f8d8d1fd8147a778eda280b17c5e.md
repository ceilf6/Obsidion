### 与本次需求相关的接口变动

1. `CornerLabelVO` / `CornerLabelDTO` 正式扩展为角标对象协议，动态角标规则不放在顶层 `textGenerationRule`。

```
// 代码块
cornerLabel?: {
  text?: string;
  type?: 1 | 2; // 1=STATIC_TEXT，2=DYNAMIC_TEXT；null 等同于 1
  cornerLabelRule?: {
    ruleId: number | string;
    rule: string;
    name?: string;
    desc?: string;
  } | null;
}
```

1. 静态角标与动态角标的字段语义：
- 静态角标：`type=STATIC_TEXT(1)`，`text` 为运营输入文本，C 端原样展示。
- 动态角标：`type=DYNAMIC_TEXT(2)`，保存时不传 `text`，通过 `cornerLabelRule.rule` 生成角标文案。
- 兼容历史数据：`cornerLabel.type` 为 `null` 或缺省时按静态角标处理。
1. M 端查询接口返回 `shelfActiveType`，前端需要根据该字段决定是否展示角标动态文本选项：
- `shelfActiveType=3` 表示公共货架，可展示动态角标能力。
- 非公共维度不展示动态角标选项，并由后端保存校验兜底。
1. M 端保存接口新增后端兼容性校验：
- 当货架维度为非公共（`shelfActiveType != 3`）时，若筛选项存在动态文本角标（`cornerLabel.type == DYNAMIC_TEXT(2)`），后端拒绝保存。
- 同一校验段落还提到系统抓取团单的不兼容项，文档描述为「任意父筛选项的 materialType == EXECUTABLE_TEXT(4) / FilterItemGroupingTypeEnum.DYNAMIC_TEXT」。该字段描述和前端 `recallType=SYSTEM` 的表达不完全一致，后续若要调整二级团单系统抓取限制，需要再和后端确认判定字段。
- 校验失败时：`success=false`，错误文案为「当前货架维度不支持该筛选项配置，请调整后重新保存」。

### 最新评论结论

- 保存接口评论明确：`CornerLabelVO` 本身就是对象，相关属性应放在 `CornerLabelVO` 内，与顶层 `textGenerationRule` 区分。
- 保存接口评论明确：`CornerLabelVO` 新增 `Integer type` 和 `RuleVO cornerLabelRule`，`type=null` 等同于 `STATIC_TEXT(1)`。
- 查询接口评论明确：查询和保存接口的 `CornerLabelVO` 均新增 `type` 和 `RuleVO cornerLabelRule`。

### 前端对应变动

1. 角标协议字段已从临时方案 `cornerLabel.textGenerationRule` 收敛到正式字段 `cornerLabel.cornerLabelRule`：
- `IFilterItemVO.cornerLabel` 类型改为 `type/text/cornerLabelRule`。
- 表单本地 `ICornerLabel` 类型改为 `type/text/cornerLabelRule`。
- 不再兼容之前临时拟定的 `cornerLabel.textGenerationRule`。
1. 表单回显与提交转换：
- M 端回显时读取 `cornerLabel.cornerLabelRule`，并根据 `cornerLabel.type` 回填「文本 / 动态文本」。
- 历史静态角标 `cornerLabel: { text }` 在无 `type` 时按文本角标回显。
- 文本角标提交 `{ type: 1, text }`。
- 动态角标提交 `{ type: 2, cornerLabelRule }`，不再提交 `text`。
1. 动态角标展示控制：
- `shelfActiveType` 为公共货架或未传入时展示「动态文本」选项。
- 明确非公共货架维度时，仅展示「文本」选项，避免前端生成后端会拒绝保存的动态角标配置。
1. 校验与统计：
- 「最多两个分组角标」统计已同时识别静态 `cornerLabel.text` 和动态 `cornerLabel.cornerLabelRule`。
- 角标相关变更仍统一归一化为 `cornerLabel`，避免临时表单字段污染上层配置。
1. 代码清理：
- 删除 `utils.ts` 中额外的 `convertCornerLabel` 二次清洗逻辑，角标协议归一化只保留在 `basic/hooks.ts` 的表单转换中。
- 保持标题动态文案继续使用顶层 `textGenerationRule`，角标动态文案只使用 `cornerLabel.cornerLabelRule`。
