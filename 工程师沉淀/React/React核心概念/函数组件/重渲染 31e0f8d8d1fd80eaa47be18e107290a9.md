# 重渲染

**React 的函数组件在每次重新渲染（re-render）时都会重新执行整个函数**。这是函数组件最核心的机制之一。

如何保存状态？通过 hooks

但要注意：**重新执行函数 ≠ 重新创建 DOM**。React 会通过 **Fiber + Diff（Reconciliation）** 来决定是否真的更新 DOM。

---

## **1️⃣ 为什么函数组件会重新执行？**

函数组件本质就是一个 **纯函数**：

```jsx
function MyComponent(props) {
  console.log("render")

  return <div>{props.name}</div>
}
```

当以下情况发生时：

- **props** 变化
- **state** 变化（useState）
- **context** 变化
- 父组件重新渲染

React 会**重新调用这个函数**：

```
MyComponent(props)
```

也就是说：

```
render -> 执行函数组件 -> 返回新的 JSX -> React diff -> 更新 DOM
```

---

## **2️⃣ React 内部实际流程（简化版）**

React Fiber 在 render 阶段会执行：

```
updateFunctionComponent()
    ↓
renderWithHooks()
    ↓
执行函数组件
```

类似这样：

```
const children = Component(props)
```

也就是：

```
FunctionComponent(props)
```

然后 React 得到新的 **VNode / ReactElement**，再和旧的进行 **diff**。

---

## **3️⃣ 例子**

```
function Counter() {
  console.log("Counter render")

  const [count, setCount] = useState(0)

  return (
    <button onClick={() => setCount(count + 1)}>
      {count}
    </button>
  )
}
```

点击按钮：

```
setState
   ↓
scheduleUpdate
   ↓
重新执行 Counter()
```

控制台：

```
Counter render
Counter render
Counter render
```

说明函数被执行了多次。

---

## **4️⃣ Hooks 为什么不会丢失状态？**

既然函数每次都会重新执行，那 useState 的状态为什么不会丢？

因为 React **把状态存储在 FiberNode 上**：

```
FiberNode
   ↓
memoizedState
   ↓
hook linked list
```

结构大概：

```
FiberNode
 ├─ type: Counter
 ├─ memoizedState -> Hook1 -> Hook2 -> Hook3
```

执行函数组件时：

```
renderWithHooks()
```

React 会按照 **hook 调用顺序** 去读取这些状态。

所以 React 才有规则：

```
Hooks 必须按顺序调用
不能写在 if / loop 里
```

---

## **5️⃣ 重新执行函数 ≠ 所有代码都重新计算**

React 提供了一些优化：

### **useMemo**

缓存计算结果

```
const result = useMemo(() => expensive(), [])
```

### **useCallback**

缓存函数引用

```
const handleClick = useCallback(() => {}, [])
```

### **React.memo**

防止子组件重新渲染

```
const Child = React.memo(function Child() {})
```

---

## **一句话总结**

**React 函数组件的本质：**

```
组件 = render函数
state存在Fiber上
每次更新都会重新执行组件函数
返回新的VNode
再进行Diff
```
