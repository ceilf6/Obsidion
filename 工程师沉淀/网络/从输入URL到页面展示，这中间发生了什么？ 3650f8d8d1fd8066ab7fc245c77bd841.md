# 从输入URL到页面展示，这中间发生了什么？

### 1.前置知识

### Chrome浏览器多进程架构

| 进程类型 | 数量 | 功能 |
| --- | --- | --- |
| **浏览器主进程** | 1个 | 主进程，管理UI、用户交互、存储等核心功能 |
| **GPU进程** | 1个 | 负责GPU加速渲染、3D效果、界面绘制 |
| **网络进程** | 1个 | 处理网络资源加载、HTTP/HTTPS请求 |
| **渲染进程** | 多个 | 每个Tab或iframe独立进程，负责页面渲染 |
| ...... 其他进程 |  |  |

### 2.概述

“从输入URL到页面展示，这中间发生了什么？”这是一道经典的面试题，可以全面的考察对知识点的掌握程度，下图是从输入 URL 到页面展示流程示意图，从中可以可以发现整个过程**需要各个进程协同处理**。
大致流程如下：
- 浏览器进程 接收用户输入的URL，将URL转发给 网络进程
- 网络进程发起真正的URL请求
- 网络进程接收响应头数据，解析响应头数据并转发给 浏览器进程
- 浏览器进程 在接收到响应头数据后，发送「提交导航」消息到渲染进程
- 渲染进程接收「提交导航」消息后，便和网络进程建立通道开始接收HTML数据
- 渲染进程向浏览器主进程「确认提交」（这是告诉浏览器进程已经准备好接收和解析页面数据）
- 浏览器进程接收「提交文档」信息之后，便开始移除旧文档，更新浏览器进程中的页面状态

### 3.导航流程

用户发出URL请求到页面开始解析，就叫「导航」。下面来阐述导航过程中的几个主要阶段。

### 3.1 用户输入

当用户在地址栏中输入关键字时，地址栏会判断输入的关键字是「**搜索内容**」，还是「**请求的URL**」。
- 如果是「搜索内容」，地址栏会使用浏览器默认的搜索引擎，来合成新的带搜索关键字。
- 如果判断输入的内容符合URL规则，那么地址栏就会根据规则加上协议，合成完整的URL。如：在地址栏输「[123.sankuai.com](http://123.sankuai.com/)」，会合成为「[https://123.sankuai.com](https://123.sankuai.com/)」。
用户输入关键字并按下回车后，在当前页面被替换为新页面之前，浏览器存在一个**beforeUnload事件**，可以用于数据清除操作或询问用户是否确认离开页面。
当用户没有beforeUnload事件或同意后，浏览器继续进入下图状态。从图中可以看到，浏览器在刚加载一个地址后，页面标签页进入加载状态，但此时还是之前的页面内容，**需要等待提交文档阶段，页面才会被替换**。

### 3.2 URL请求过程

进入资源请求过程，浏览器进程会通过**进程间通讯（IPC）**把URL发给网络进程，网络进程接收到URL后才整正发起URL请求。具体流程：
- 网络进程查找是否有缓存资源。
- 如果有缓存资源，直接返回资源给浏览器进程。
- 如果没有缓存资源，进入网络请求流程。通过DNS解析获取域名的IP地址，如果是https协议，需建立TLS链接。
- 利用IP地址和服务器建立TCP连接。
- 建立连接后，浏览器会构建请求头、请求行等信息，并将域名相关的Cookie等数据一并加入请求头中，向服务器发送请求信息。
- 服务器接收信息后，会根据请求信息返回响应信息

### 3.2.1 重定向

接收到响应数据后，网络进程开始解析响应数据，如果状态码是301或302，说明服务器需要浏览器将页面重定向到其他URL。这时网络进程会从响应头的Location字段里读取需要重定向的URL，重新发起请求。

### 3.2.2 响应数据类型处理

浏览器会根据响应头中的 Content-Type进行不同处理，如 Content-Type 是 application/octet-stream, 显示数据时字节流类型，浏览器会按照下载类型来处理该请求。当 Content-Type 为 text/html 的HTML格式，浏览器继续导航流程。

### 3.3 准备渲染进程

打开一个新页面的策略：
- 通常情况，打开一个新页面会单独使用一个**渲染进程**
- 如果从A页面打开B页面，A和B属于**同一站点**，那么B页面会**复用**A页面的渲染进程
- **同一站点**：根域名+协议 相同。
`javascript 	<https://fedo.sankuai.com> 	<https://123.sankuai.com> 	<https://123.sankuai.com:8080>` 	
- **根域名**：二级域名 + 顶级域名。
`javascript 	// 123.sankuai.com 	sankuai.com（根域名）= sankuai（二级域名）+ .com（顶级域名）` 	
渲染进程准备好后，还不能立即进入文档解析状态，因为此时的文档数据还在网络进程中，并没有提交给渲染进程，所以下一步进入提交文档阶段。

### 3.4 提交文档

所谓提交文档，就是**浏览器进程将网络进程接收的HTML数据发给渲染进程**。具体流程：
- 浏览器进程接收到网络进程的响应数据后，向渲染进程发起「提交文档」信息
- 浏览器进程接收到「提交文档」信息后，与网络进程建立IPC通讯
- 等文档数据传输完后，渲染进程会返回「确认提交」的消息给浏览器进程
- 浏览器进程收到「确认提交」信息后，开始更新浏览器状态

### 4. 渲染流程

渲染模块在执行过程中会被划分为多个子阶段，输入的HTML经过这些子阶段输出为像素，这个处理过程称为**渲染流水线**。
按照渲染的时间顺序，流水线可分为如下几个子阶段：构建 DOM 树、样式计算、布局阶段、分层、图层绘制、栅格化和合成。需要关注以下三点内容：
- 每个子阶段开始的**输入内容**
- 每个子阶段的**处理过程**
- 每个子阶段生成的**输出内容**

### 4.1 构建DOM树

计算机无法直接理解和使用HTML，所以需要将HTML转换为浏览器能理解的结构——**DOM树**。从下图可以看出，此阶段的输入内容是HTML，经过HTML解析器解析，最终输出树状结构的DOM树。

### 4.2 样式计算

样式计算的目的是为了**计算每个DOM节点中每个元素的具体样式**，大体分为三个阶段。

### 4.2.1 把 CSS 转换为浏览器能理解的结构

CSS 主要来源有3种：
- 通过 link 引入的 CSS 文件
- <style> 标签内的 CSS
- 元素的style属性内嵌的 CSS
当渲染引擎接收到CSS文本后，会执行一个转换操作（Parse），将CSS文本转换为浏览器能理解的结构——**styleSheets**。

### 4.2.2 转换样式表中的属性值，使其标准化

渲染引擎会将部分CSS属性进行标准化处理。如 2em -> 32px, blue -> rbg(0, 0, 255)

### 4.2.3 计算DOM树中每个节点的具体样式

计算DOM树每个节点的样式，涉及到「**CSS继承**」和「**CSS层叠**」。
- **CSS继承**
所有子节点都继承了父节点的样式。
- **CSS 层叠**
定义如何合并多个源的属性的算法。四大原则(优先级依次降低)：

1. 
    - **重要性**：*!important*
2. 
    - **特殊性**：*内联样式 > ID选择器 > 类选择器 > 元素选择器*
3. 
    - **来源顺序**：后定义的样式覆盖先定义的样式
4. 
    - **继承**

### 4.3 布局

现在有了DOM树和StyleSheets样式，还不足以显示页面，因为还不知道元素的**几何位置**。计算元素的几何位置称为“**布局**”。整个阶段分为「**创建布局树**」和「**布局计算**」。

### 4.3.1 创建布局树

DOM树中包含了很多不可见的元素，如 head 标签，使用 display: none 属性的元素。在显示页面之前，需要构建一个**只包含可见元素的布局树**。
为了构建布局树，浏览器大体完成以下工作：
- 遍历DOM树的所有可见节点，构建到布局树中。
- 忽略掉不可见的节点。

### 4.3.2 布局计算

为了计算节点的**坐标位置**，将这些信息保存到布局树中。

### 4.4 分层阶段

浏览器中为了实现复杂的3D变换、页面滚动或 z-index 的z轴排序时，渲染引擎需要为一些特定的节点生成专门的图层，构建一个**图层树**。从下图可以发现浏览器的页面被分成很多个图层，这些图层叠加后形成了最终的页面。
布局树中并不是每一个节点都生成一个图层，如果节点没有对应的图层，那么这个节点从属于父节点的图层，图中span标签从属于其父节点div标签的图层。
那么布局树中的节点如何产生图层？可通过以下两种方式：
- 拥有**层叠上下文属性**的元素会被提升为单独的图层
页面是一个二维平面，层叠上下文可以让HTML元素具有三维概念，定位属性的元素（position、z-index）、定义透明属性的元素（opacity）、使用 CSS 滤镜的元素（filter）等，都拥有**层叠上下文属性**。
- **需要剪切的地方**也会创建图层
图中限制了div宽度和高度后导致内容溢出，此时产生了裁切，渲染引擎会将裁切的内容显示到div区域。

### 4.5 图层绘制

渲染引擎会将图层的绘制，拆分为多个小的**绘制指令**，进而形成一个**绘制列表**。下图中示例了[123.sankuai.com](http://123.sankuai.com/)站点 document 节点的绘制列表（红框处）。

### 4.6 栅格化

绘制列表是用来记录绘制顺序和绘制指令的列表，而实际上绘制操作是由渲染引擎中的**合成线程**来完成的。结合下图看看渲染主线程和合成线程的关系：
当准备好绘制列表后，渲染主线程会把该列表**提交（commit）**给合成线程。基于性能开销，**合成线程会将图层划分为多个图块**。
合成线程会按照视口附近的图块来优先生成位图，实际生成位图的操作是由栅格化来执行。**所谓栅格化，就是将图块转换为位图**。渲染进程维护了一个栅格化线程池来执行栅格化。也可以将栅格化指令发送给GPU进程，在GPU中进行快速栅格化。

### 4.7 合成和显示

当所有图块都被栅格化处理后，合成线程会生成一个**绘制图块的命令——“DrawQuad”**，将该命令发送给浏览器进程。浏览器进程根据DrawQuad命令，将其页面绘制到内存中，最终显示到屏幕上。

### 4.8 渲染流水线总结

结合上图总结如下：

1. 
    - **渲染进程将 HTML 内容转换为能够读懂的 DOM 树结构。**
2. 
    - **渲染引擎将 CSS 样式表转化为浏览器可以理解的 styleSheets，计算出 DOM 节点的样式。**
3. 
    - **创建布局树，并计算元素的布局信息。**
4. 
    - **对布局树进行分层，并生成分层树。**
5. 
    - **为每个图层生成绘制列表，并将其提交到合成线程。**
6. 
    - **合成线程将图层分成图块，并在光栅化线程池中将图块转换成位图。**
7. 
    - **合成线程发送绘制图块命令 DrawQuad 给浏览器进程。**
8. 
    - **浏览器进程根据 DrawQuad 消息生成页面，并显示到显示器上。**

### 5. 补充

### 5.1 更新了元素的几何属性（重排）

如果通过 Javascript 或 CSS 修改元素的几何属性，如改变元素的宽高，那么浏览器会**触发重新布局及后续一系列子阶段**，这个过程叫重排。重排基本会更新渲染流水线，开销最大。

### 5.2 更新了元素的绘制属性（重绘）

如果通过 Javascript 更改某些元素的背景色，因为没有改变元素的几何位置，所以**直接进入绘制阶段及后续一系列子阶段**，这个过程叫重绘。相对于重排，重绘省去了布局和分层阶段，所以执行效率会更高。

### 5.3 直接合成阶段

如果更改一个既不需要布局也不要绘制的属性呢？渲染引擎会跳过布局和绘制，只执行后续的合成操作。比如我们使用 CSS 的 transform 来实现，这样可以避开布局和绘制，直接在非主线程上进行合成操作，效率最高。
