# AJAX

AJAX 就是浏览器赋予 JS 的一套 API ，通过这套 API 能够使 JS 具备网络通信的能力

# 历史

浏览器作为用户代理本身具备网络通信的能力，但在早起，浏览器并没有把网络能力开放给 JS

最早是微软在 IE 浏览器中把这个能力向 JS 开放，让 JS 可以在代码中实现发送请求，这项技术被命名为 AJAX

Asynchronous Javascript And XML

IE 使用了一套 API 来完成请求的发送，这套 API 主要依靠一个构造函数完成。该构造函数的名称为 XMLHttpRequest ，简称 XHR ，所以这套 API 又称为 XHR API

由于 XHR API 有很多缺陷，在 HTML5 和 ES6 发布之后，产生了一套更完善的 API 发送请求。这套 API 主要是 fetch 函数，称之为 fetch API

无论 XHR 还是 fetch ，都是实现 ajax 的技术手段，只是 API 不同

# XHR API

```jsx
var xhr = new XMLHttpRequest(); //创建发送请求的对象
xhr.onreadystatechange = function () {
  //当请求状态发生改变时运行的函数
  // xhr.readyState： 一个数字，用于判断请求到了哪个阶段
  // 0: 刚刚创建好了请求对象，但还未配置请求（未调用open方法）
  // 1: open方法已被调用
  // 2: send方法已被调用
  // 3: 正在接收服务器的响应消息体
  // 4: 服务器响应的所有内容均已接收完毕
  // xhr.responseText： 获取服务器响应的消息体文本
  // xhr.getResponseHeader("Content-Type") 获取响应头Content-Type
};
xhr.open('请求方法', 'url地址'); // 配置请求
xhr.setRequestHeader('Content-Type', 'application/json'); // 设置请求头
xhr.send('请求体内容'); // 构建请求体，发送到服务器，如果没有请求体，传递null

```

# Fetch API

```jsx
const resp = await fetch('url地址', {
  // 请求配置对象，可省略，省略则所有配置为默认值
  method: '请求方法', // 默认为GET
  headers: {
    // 请求头配置
    'Content-Type': 'application/json',
    a: 'abc',
  },
  body: '请求体内容', // 请求体
  incredential: 'include'
}); // fetch会返回一个Promise，该Promise会在接收完响应头后变为fulfilled

resp.headers; // 获取响应头对象
resp.status; // 获取响应状态码，例如200
resp.statusText; // 获取响应状态码文本，例如OK
resp.json(); // 用json的格式解析即将到来的响应体，返回Promise，解析完成后得到一个对象
resp.text(); // 用纯文本的格式解析即将到来的响应体，返回Promise，解析完成后得到一个字符串

```
