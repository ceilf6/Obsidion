# 内存泄漏

## **一句话结论**

**JS 闭包本身不是内存泄漏的罪魁祸首，**

**“长期被引用、又不再需要的闭包里的数据”才是。**

---

## **为什么闭包“看起来”会导致内存泄漏？**

先回顾一下闭包👇

```
function outer() {
  const bigData = new Array(1000000).fill('*')
  return function inner() {
    console.log(bigData.length)
  }
}

const fn = outer()
```

这里发生了什么：

- inner **引用了** outer 里的 bigData
- 只要 fn 还存在，bigData 就 **不能被 GC 回收**
- 即使你已经“用不上” bigData 了

👉 **如果 fn 被长期保存（全局变量、缓存、事件、定时器）**，

那就可能造成 **内存无法释放**。

---

## **真正导致内存泄漏的常见场景**

### **1️⃣ 闭包 + 全局变量**

```
let cache

function create() {
  const data = new Array(1000000)
  cache = () => data
}
create()
```

- cache 是全局的
- 闭包一直活着
- data 永远不会被回收 ❌

---

### **2️⃣ 闭包 + 事件监听（最常见）**

```
function bind() {
  const huge = { /* 很大的对象 */ }

  element.addEventListener('click', function () {
    console.log(huge)
  })
}
```

如果：

- element 一直存在
- 却 **从不 removeEventListener**

👉 huge 会一直被引用

✅ 正确姿势：

```
const handler = () => console.log(huge)
element.addEventListener('click', handler)

// 不用了
element.removeEventListener('click', handler)
```

---

### **3️⃣ 闭包 + 定时器 / Promise**

```
function start() {
  const data = fetchBigData()

  setInterval(() => {
    console.log(data)
  }, 1000)
}
```

- setInterval 永远执行
- data 永远存活

👉 不 clear，就不释放

---

### **4️⃣ 意外的“缓存型闭包”**

```
function memo() {
  const cache = {}
  return function (key, value) {
    cache[key] = value
  }
}
```

- cache 越来越大
- 没有淘汰策略
- 逻辑上不是 bug，但 **内存会炸**

---

## **那闭包什么时候是“安全的”？**

✅ **短生命周期**

```
(() => {
  const tmp = 123
  console.log(tmp)
})()
```

✅ **能被释放**

```
let fn = outer()
fn = null // 引用断开，闭包可回收
```

✅ **不捕获大对象**

```
// 尽量只捕获必要的
```

---

## **判断是不是闭包内存泄漏的口诀 🧠**

> 闭包里的变量，会不会：
> 
1. 被长期引用？
2. 又不再需要？
3. 还很大？

**三条同时满足 = 高危 ⚠️**

---

## **面试官版总结（可以直接背）**

> 闭包本身不会导致内存泄漏，
> 

> 内存泄漏的根本原因是
> 
> 
> **不必要的长期引用**
> 

> 如果闭包被全局变量、事件监听、定时器等持有，
> 

> 并且捕获了大对象，就可能造成内存无法回收。
>

# **一、Chrome DevTools：如何「实锤」闭包内存泄漏**

> 面试最加分的不是“我觉得”，而是：
> 

> 我用 Heap Snapshot 看过
> 

---

## **1️⃣ 构造一个“标准泄漏”的闭包**

```
let leak

function createLeak() {
  const big = new Array(1_000_000).fill('*')
  leak = function () {
    return big.length
  }
}

createLeak()
```

---

## **2️⃣ DevTools 实操步骤（必会）**

1. 打开 **Chrome DevTools**
2. 👉 Memory
3. 👉 Heap snapshot
4. 👉 Take snapshot
5. 在 Console 执行多次：

```
createLeak()
```

1. 
2. 再拍一个 snapshot
3. 对比 **Objects count / Retained size**

你会看到：

- Closure (createLeak) 还活着
- big 被 leak → [[Environment]] 持有
- GC **无法回收**

📌 **关键词**：Retainers 面板

---

## **3️⃣ 修复后验证（面试官最爱）**

```
leak = null
```

再拍一次 snapshot：

- big 消失
- 内存下降

👉 **这就是“我亲手验证过”的证据**

# **二、React 中的闭包内存泄漏（高频雷区）**

## **1️⃣ useEffect + 闭包 + 事件**

❌ 错误示例：

```
useEffect(() => {
  const huge = new Array(1000000)

  window.addEventListener('resize', () => {
    console.log(huge.length)
  })
}, [])
```

问题：

- 匿名函数无法 remove
- huge 永远被引用

---

### **✅ 正确写法**

```
useEffect(() => {
  const huge = new Array(1000000)

  const handler = () => {
    console.log(huge.length)
  }

  window.addEventListener('resize', handler)

  return () => {
    window.removeEventListener('resize', handler)
  }
}, [])
```

📌 面试一句话：

> useEffect 清理函数不只是“规范”，
> 

> 而是防止闭包长期引用导致内存泄漏。
> 

---

## **2️⃣ 定时器闭包泄漏**

```
useEffect(() => {
  const data = fetchBigData()

  const id = setInterval(() => {
    console.log(data)
  }, 1000)

  return () => clearInterval(id)
}, [])
```

---

## **3️⃣ useRef：闭包“瘦身”神器**

```
const dataRef = useRef(null)

useEffect(() => {
  dataRef.current = fetchBigData()
}, [])

function handler() {
  console.log(dataRef.current)
}
```

👉 **避免把大对象塞进闭包**

---

# **三、Vue 中的闭包内存泄漏**

## **1️⃣ watch + 闭包**

```
mounted() {
  const huge = new Array(1000000)

  this.$watch('count', () => {
    console.log(huge)
  })
}
```

如果组件没正确销毁 → 泄漏

---

### **✅ Vue 3 正确方式**

```
import { watch, onUnmounted } from 'vue'

const stop = watch(count, () => {
  console.log(huge)
})

onUnmounted(() => stop())
```

---

## **2️⃣ 自定义事件没解绑**

```
bus.on('event', () => {
  console.log(huge)
})
```

📌 记住一句话：

> Vue 组件销毁 ≠ 所有闭包自动释放
>

# **四、真实业务中的“隐形闭包泄漏”**

## **1️⃣ 防抖 / 节流**

```
function debounce(fn) {
  let timer
  return function () {
    timer = setTimeout(fn, 300)
  }
}
```

- timer
- fn
- 参数
    
    都可能被长期引用
    

✅ 解决：

- 提供 cancel
- 生命周期结束时调用

---

## **2️⃣ 缓存闭包（面试官常挖）**

```
function memo() {
  const cache = new Map()
  return (k, v) => cache.set(k, v)
}
```

📌 正确追问点：

- 是否有 LRU？
- 是否有限制大小？
- 是否会过期？

你可以这样答 👇

### **Q1：闭包会导致内存泄漏吗？**

> 不会必然导致，但可能造成长期引用。
> 

### **Q2：什么时候会？**

> 闭包被全局变量、事件、定时器持有，并捕获大对象。
> 

### **Q3：如何排查？**

> Chrome DevTools → Heap Snapshot → Retainers。
> 

### **Q4：React / Vue 中怎么防？**

> useEffect 清理、副作用解绑、避免大对象进闭包。
> 

### **Q5：如何设计避免？**

> 控制生命周期、弱引用、ref、取消机制。
>
