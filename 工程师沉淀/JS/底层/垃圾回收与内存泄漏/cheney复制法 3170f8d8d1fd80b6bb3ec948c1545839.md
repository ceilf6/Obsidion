# cheney复制法

---

**核心流程**

```
遍历根/Remembered Set，对每个槽调用 CheckAndScavengeObject
                    ↓
          ScavengeObject(slot, object)
                    ↓
    读 MapWord = object->map_word(kRelaxedLoad)
           ↙                   ↘
IsForwardingAddress?          ToMap() = 真实 Map
  已复制过了                      还没处理
  更新槽指针到新地址         →  EvacuateObject → TryMigrateObject
  直接返回                              ↓
                            CAS 原子写入 forwarding pointer
                            将对象内容 CopyBlock 到 To-space
```

---

**`TryMigrateObject` 中的关键 CAS**（[scavenger.cc](http://scavenger.cc/)）：

```cpp
// 原子地把 MapWord 从 "真实 Map" 换成 "转发地址 target"
if (!source->relaxed_compare_and_swap_map_word_forwarded(
        MapWord::FromMap(map), target)) {
    // CAS 失败 = 另一个线程已经复制了它，allocator_ 退回分配空间
}
// CAS 成功后，才 memcpy 内容
heap()->CopyBlock(target.address() + kTaggedSize, ...);
```

---

**死对象如何"消灭"的**

Cheney 算法**根本不扫描死对象**，只遍历可达图：

| 状态 | MapWord | 处理 |
| --- | --- | --- |
| **存活、第一次遇到** | 真实 Map 指针 | `EvacuateObject` → 复制 → 安装 forwarding pointer |
| **存活、已被复制** | Forwarding Address | 直接更新槽指针，不重复复制 |
| **死亡** | 真实 Map（从未被访问） | 永远不会被 `ScavengeObject` 调用到 |

From-space 里**没有 forwarding pointer 的对象 = 死对象**，但不需要逐个 free 它们——GC 结束后整个 From-space 被 `SwapSemiSpaces()` 变成下一次的 To-space，**整块 reset，O(1) 完成回收**。

---

**与三色标记的本质区别**

Mark-Compact 需要 bitmap 记录标记状态（白/灰/黑），因为它原地整理、不移动。

Cheney 不需要 bitmap——**forwarding pointer 本身就是"已复制"的标记**，同时承担了颜色位 + 新地址两个职责。
