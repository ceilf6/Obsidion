状态管理分为两个部分

# 1. 状态维护

关注谁对状态负责

- 组件自身使用：Vue2的data 以及 Vue3各种响应式API: ref, reactive, computed
    
    [Reactivity API 响应式](Vue3/Reactivity%20API%20%E5%93%8D%E5%BA%94%E5%BC%8F%203050f8d8d1fd807989b1e59b5a560fb8.md) 
    
    [计算属性computed 和 方法methods 有什么区别？](Vue2/%E9%85%8D%E7%BD%AE%202f90f8d8d1fd80b1bf1df63d10d85ce2.md) 
    
- 多个组件共享
    - 跨层级不严重：**状态提升**到最近公共祖先上
    - 如果跨层级严重：
        1. Vue 内置的 **provide, inject** （和 React 的 Context 都是**生产者消费者模式**）
            
            祖先组件provide => 中间组件 => 子孙组件inject
            
            ```jsx
            import { provide, ref } from 'vue'
            const count = ref(0)
            **provide**('count', count) // 父组件
            ```
            
            ```jsx
            import { inject } from 'vue'
            const count = **inject**('count') // 子孙组件
            ```
            
        2. **全局**状态
            - Vuex
                
                [state     → 数据
                getter    → 计算属性
                mutation  → 修改 state（同步）
                action    → 异步逻辑](Vue2/%E6%95%B0%E6%8D%AE%E5%85%B1%E4%BA%AB%20vuex%203020f8d8d1fd807d928de5db04f8194d.md) 
                
            - Pinia
                
                [pinia](%E7%8A%B6%E6%80%81%E7%AE%A1%E7%90%86/pinia%2031c0f8d8d1fd80d5a3fec1fe5c47bae3.md)
                
        3. 事件总线: 本质就是**发布订阅模式**
            
            [事件总线 发布订阅模式](Vue2/%E4%BA%8B%E4%BB%B6%E6%80%BB%E7%BA%BF%20%E5%8F%91%E5%B8%83%E8%AE%A2%E9%98%85%E6%A8%A1%E5%BC%8F%203020f8d8d1fd80d2909ffe2d4c0abb0c.md) 
            
        4. **组合式函数，**类似于React的 **custom hook** ，**在函数内部维护数据后暴露给外面使用**
            
            ```jsx
            // useCounter.js
            import { ref } from 'vue'
            const count = ref(0)
            export function useCounter() {
              function add() {
                count.value++
              }
              return { count, add }
            }
            ```
            
            ```jsx
            const { count, add } = useCounter()
            ```
            
        5. Router状态: 配置**路由**插件，利用 **URL本身就是状态**，通过 **url** 上的哈希值等等进行匹配状态
            
            [插件>路由、状态管理](Vue2/%E6%8F%92%E4%BB%B6%20%E8%B7%AF%E7%94%B1%E3%80%81%E7%8A%B6%E6%80%81%E7%AE%A1%E7%90%86%202fd0f8d8d1fd8069a0e0ff10a7a72b9d.md) 
            
        6. **Server State**: 如果状态来自于**服务器**，那么就不像上面客户端数据简单，因为存在loading状态、缓存、数据同步、重新获取、并发等问题
            
            用 **Vue Query**
            

# 2. 状态通信

关注如何获取状态，让状态在组件树中流动

**单向数据流**确保状态更新的可追踪、可预测

[组件通信](%E7%8A%B6%E6%80%81%E7%AE%A1%E7%90%86/%E7%BB%84%E4%BB%B6%E9%80%9A%E4%BF%A1%202fc0f8d8d1fd8054999fedb48cb0dad9.md)

- 父传子：prop传递
- 子传父：
    - **上报**事件 **$emit**
    - 通过组件实例属性 **$listeners** ，和 React 类似父组件**下放权力**给子组件
- 兄弟间
- 跨层级
- ref引用，直接获取组件元素对象
