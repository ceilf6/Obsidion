# AT&T VPS 直连 SOCKS5 从零配置

这份文档适用于现在的情况：本地网络已经可以直接连到 VPS，不再需要先经过机场前置节点。你现在只需要 VPS IP 和 root 密码，就可以先 SSH 登录 VPS，再在 VPS 上安装一个 SOCKS5 服务，最后让 Clash Verge 或 Shadowrocket 直接连这个 SOCKS5。

下面假设 VPS IP 是：

```
108.242.235.178
```

不要把 root 密码填进 Clash / Shadowrocket。root 密码只用于 SSH 登录 VPS；SOCKS5 会单独生成一个密码。

## 1. 本地先确认能直连 SSH

在 Mac 终端执行：

```bash
VPS_IP="108.242.235.178"
nc -vz -G 5 "${VPS_IP}" 22
```

看到类似下面的结果，说明当前网络可以直接连到 VPS 的 SSH 端口：

```
Connection to 108.242.235.178 port 22 [tcp/ssh] succeeded!
```

如果这里失败，先不要继续安装 SOCKS5。需要检查当前网络、VPS 是否开机、服务商防火墙是否放行了 `22/tcp`。

## 2. 用 root 密码登录 VPS

继续在 Mac 终端执行：

```bash
ssh root@108.242.235.178
```

第一次登录时，如果提示是否信任指纹，输入：

```
yes
```

然后输入你的 root 密码。密码输入时终端不会显示，这是正常的。

如果提示 `Permission denied`，说明 root 密码不对，或者服务商禁用了 root 密码登录，需要去 VPS 面板检查登录方式。

## 3. 在 VPS 上安装 SOCKS5

登录到 VPS 后，把下面整段命令复制到 VPS 终端执行。

默认配置：

- SOCKS5 用户名：`att`
- SOCKS5 端口：`33123`
- SOCKS5 密码：自动随机生成

```bash
set -e

GOST_VERSION="3.2.6"
PROXY_USER="att"
PROXY_PORT="33123"

apt update
apt install -y ca-certificates curl openssl tar ufw

PROXY_PASS="$(openssl rand -hex 16)"

ARCH="$(uname -m)"
case "${ARCH}" in
  x86_64)
    GOST_ARCH="amd64"
    ;;
  aarch64|arm64)
    GOST_ARCH="arm64"
    ;;
  *)
    echo "不支持的 CPU 架构：${ARCH}"
    exit 1
    ;;
esac

cd /tmp
curl -fL -o gost.tar.gz "https://github.com/go-gost/gost/releases/download/v${GOST_VERSION}/gost_${GOST_VERSION}_linux_${GOST_ARCH}.tar.gz"
tar -xzf gost.tar.gz
install -m 755 gost /usr/local/bin/gost

mkdir -p /etc/gost
cat > /etc/gost/config.yaml <<EOF
services:
- name: socks5
  addr: ":${PROXY_PORT}"
  handler:
    type: socks5
    auth:
      username: "${PROXY_USER}"
      password: "${PROXY_PASS}"
  listener:
    type: tcp
EOF

cat > /etc/systemd/system/gost.service <<EOF
[Unit]
Description=GOST SOCKS5 Proxy
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/usr/local/bin/gost -C /etc/gost/config.yaml
Restart=on-failure
RestartSec=5s

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now gost

ufw allow 22/tcp
ufw allow "${PROXY_PORT}/tcp"
ufw --force enable

echo
echo "SOCKS5 信息如下，请保存："
echo "Host: 108.242.235.178"
echo "Port: ${PROXY_PORT}"
echo "Username: ${PROXY_USER}"
echo "Password: ${PROXY_PASS}"
echo

systemctl status gost --no-pager
```

注意：如果复制后终端里变成了 `"<https://github.com/...>"`，要删掉尖括号 `< >`。正确格式是 `"<https://github.com/>..."`。

如果 VPS 服务商面板里还有单独的防火墙 / Security Group，也要在那里放行：

```
33123/tcp
```

## 4. 在 VPS 上自测 SOCKS5 是否工作

还是在 VPS 终端里执行：

```bash
curl -x "socks5h://127.0.0.1:33123" --proxy-user "att:bc3fef018c62ea9b12828986901c1063" https://api.ipify.org
```

把 `你的SOCKS5密码` 换成上一步输出的 `Password`。

如果能输出一个 IP，说明 VPS 本机上的 SOCKS5 服务已经正常。

也可以检查服务和监听端口：

```bash
systemctl status gost --no-pager
ss -lntp | grep 33123
ufw status
```

## 5. 回到 Mac 测试远程 SOCKS5 端口

退出 VPS：

```bash
exit
```

在 Mac 终端执行：

```bash
nc -vz -G 5 108.242.235.178 33123
```

成功时会看到：

```
Connection to 108.242.235.178 port 33123 [tcp/*] succeeded!
```

再用 SOCKS5 真实请求一次：

```bash
curl -x "socks5h://108.242.235.178:33123" --proxy-user "att:你的SOCKS5密码" <https://api.ipify.org>
```

如果这里能输出 VPS 的出口 IP，说明本地已经可以直接通过 VPS SOCKS5 出网。

## 6. Clash Verge 直连配置

打开 Clash Verge 的 `全局扩展脚本 Script`，粘贴下面脚本。

只需要改一个地方：

```jsx
const VPS_PASS = "替换成你的SOCKS5密码";
```

完整脚本：

```jsx
function main(config) {
  const VPS_NAME = "ATT-Residential";
  const CLAUDE_GROUP = "Claude-ATT";

  const VPS_HOST = "108.242.235.178";
  const VPS_PORT = 33123;
  const VPS_USER = "att";
  const VPS_PASS = "bc3fef018c62ea9b12828986901c1063";

  config.proxies = config.proxies || [];
  config["proxy-groups"] = config["proxy-groups"] || [];
  config.rules = config.rules || [];

  config.proxies = config.proxies.filter((p) => p.name !== VPS_NAME);
  config["proxy-groups"] = config["proxy-groups"].filter(
    (g) => g.name !== CLAUDE_GROUP,
  );
  config.rules = config.rules.filter((rule) => !rule.includes(CLAUDE_GROUP));

  config.proxies.push({
    name: VPS_NAME,
    type: "socks5",
    server: VPS_HOST,
    port: VPS_PORT,
    username: VPS_USER,
    password: VPS_PASS,
    udp: false,
  });

  config["proxy-groups"].push({
    name: CLAUDE_GROUP,
    type: "select",
    proxies: [VPS_NAME, "DIRECT"],
  });

  config.rules = [
    `DOMAIN-SUFFIX,anthropic.com,${CLAUDE_GROUP}`,
    `DOMAIN-SUFFIX,claude.ai,${CLAUDE_GROUP}`,
    ...config.rules,
  ];

  return config;
}
```

推荐 Clash Verge 设置：

```
代理模式：规则
Claude-AT&T：选择 AT&T-Residential
虚拟网卡模式 / TUN：开启
IPv6：关闭
```

如果你想让所有流量都走这个 VPS，可以临时切到 `全局` 模式，并选择 `AT&T-Residential`。只访问 Claude 时，优先用 `规则` 模式。

## 7. iPhone / Shadowrocket 直连配置

添加一个 SOCKS5 节点：

```
Type / 类型：Socks5 或 Socks
Address / 地址：108.242.235.178
Port / 端口：33123
User / 用户名：att
Password / 密码：填 VPS 上输出的 SOCKS5 密码
Remark / 备注：AT&T-Residential
```

这里和旧流程不同：不需要选择“代理通过”前置节点。如果 Shadowrocket 有 `Proxy Through / 代理通过`，保持不选或直连。

## 9. 常见问题

### `ssh root@108.242.235.178` 连不上

先测：

```bash
nc -vz -G 5 108.242.235.178 22
```

如果 `22/tcp` 不通，问题还在 SSH 直连层面，先检查 VPS 是否开机、服务商防火墙是否放行 `22/tcp`。

### `33123` 端口连不上

在 VPS 上检查：

```bash
systemctl status gost --no-pager
ss -lntp | grep 33123
ufw status
```

如果 VPS 本机正常，但 Mac 连不上，通常是服务商面板防火墙没有放行 `33123/tcp`。

### `curl: (3) URL using bad/illegal format`

检查你的 `curl` 命令里是不是带了尖括号：

```bash
curl -fL -o gost.tar.gz "<https://github.com/...>"
```

这是错误写法。改成：

```bash
curl -fL -o gost.tar.gz "<https://github.com/>..."
```

然后重新执行第 3 节的安装命令。

### SOCKS5 密码忘了

在 VPS 上查看：

```bash
cat /etc/gost/config.yaml
```

也可以重新生成密码后重启服务：

```bash
PROXY_PASS="$(openssl rand -hex 16)"
sed -i "s/password: .*/password: \"${PROXY_PASS}\"/" /etc/gost/config.yaml
systemctl restart gost
echo "${PROXY_PASS}"
```

然后把 Clash Verge / Shadowrocket 里的密码同步改掉。

```jsx
function main(config) {
  const FRONTIER_NAME = "US-Frontier-Residential";
  const DIALER_GROUP = "Frontier-前置机场";
  const CLAUDE_GROUP = "Claude-住宅出口";

  const FRONTIER_HOST = "108.242.235.178";
  const FRONTIER_PORT = 33123;
  const FRONTIER_USER = "frontier";
  const FRONTIER_PASS = "bc3fef018c62ea9b12828986901c1063";

  const preferredDialers = [
    "🇭🇰 香港S01",
    "🇯🇵 日本S01 | IEPL",
    "🇺🇲 美国S01 | IEPL | x1.5",
    "🇺🇲 美国S02 | IEPL | x1.5",
  ];

  config.proxies = config.proxies || [];
  config["proxy-groups"] = config["proxy-groups"] || [];
  config.rules = config.rules || [];

  const existingProxyNames = new Set(config.proxies.map((p) => p.name));
  const dialerProxies = preferredDialers.filter((name) => existingProxyNames.has(name));

  if (dialerProxies.length === 0) {
    throw new Error("没有找到可用前置机场节点，请检查节点名称");
  }

  config.proxies = config.proxies.filter((p) => p.name !== FRONTIER_NAME);
  config["proxy-groups"] = config["proxy-groups"].filter(
    (g) => g.name !== DIALER_GROUP && g.name !== CLAUDE_GROUP
  );
  config.rules = config.rules.filter((rule) => !rule.includes(CLAUDE_GROUP));

  config["proxy-groups"].push({
    name: DIALER_GROUP,
    type: "select",
    proxies: dialerProxies,
  });

  config.proxies.push({
    name: FRONTIER_NAME,
    type: "socks5",
    server: FRONTIER_HOST,
    port: FRONTIER_PORT,
    username: FRONTIER_USER,
    password: FRONTIER_PASS,
    udp: false,
    "dialer-proxy": DIALER_GROUP,
  });

  config["proxy-groups"].push({
    name: CLAUDE_GROUP,
    type: "select",
    proxies: [FRONTIER_NAME, DIALER_GROUP, "DIRECT"],
  });

  config.rules = [
    `DOMAIN-SUFFIX,anthropic.com,${CLAUDE_GROUP}`,
    `DOMAIN-SUFFIX,claude.ai,${CLAUDE_GROUP}`,
    ...config.rules,
  ];

  return config;
}
```
