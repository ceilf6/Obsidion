# 多智能体共享事实

https://github.com/ceilf6/Lab/commit/5ccfb7468949e43a4b0567c73744019e974240c2

首先明确上下文是如何分割、沙盒化的：[通过 **NodeJS进程边界**+最小消息面 实现不同Agent的上下文分割](SubAgent%20&%20A2A%203230f8d8d1fd80a5a8f9e18df575f03b.md) 

那么本质要解决的问题就是如何处理 NodeJS 跨进程协作共享、维护内容

类似于React状态上移，主Agent持有事实来源，在调用SubAgent的时候下发事实快照，子代理在a2a返回响应时返回更新包，主Agent进行合并

1. 主 Agent 是唯一写入者（single writer），持有 `facts` 真相。
    
    在 types.ts 新增可序列化 ProjectFactsSnapshot（把 Set/Map 转成数组/对象），因为 process 隔离子进程不能直接传 Set/Map
    
2. 调用 SubAgent 时下发 `factsSnapshot + revision`。
3. SubAgent 返回 `factDelta + baseRevision`（不要回整份 state，而只是 diff部分 ）。
4. 主 Agent 按队列串行合并，每次合并后 `revision++`。

竞态问题 - 多子代理并发返回时，核心是“**串行 reducer + 版本校验**”：

```tsx
type FactDelta = { baseRevision: number; ops: FactOp[] };

enqueue(delta);
processQueueOneByOne(() => {
  if (delta.baseRevision !== facts.revision) {
    delta = rebase(delta, facts); // 基于当前事实重放/重算
  }
  facts = applyOps(facts, delta.ops); // 原子合并
  facts.revision++;
});
```

冲突策略建议：

1. `Set/Map` 类事实：用可交换操作（`add/remove`）合并。
2. 标量字段（如 `buildStatus`）：用明确规则（如时间戳 LWW 或优先级）。
3. 高风险字段：CAS 失败就丢回重算或重试。
