# 名词

和 LLM 做沟通，尽可能多的使用大语言模型能力

将固定的部分例如通过程序编写用 Function Calling 包裹在 MCP 中暴露给大模型使用

而灵活的需求部分就是用户的输入

Context: 上下文，背景信息

Prompt: 当前工作要求

Memory: 多轮对话过程中，前面的信息

获取参数以外的信息

- LLM 本身只能词语接龙（预测下一个单词是什么，选择词表中概率最大的那一个），为了有例如 上网搜索Search 等能力需要写一段程序供 LLM 使用 ⇒ 智能体
- RAG 检索增强生成：搜索本地文件能力，通过语义匹配向量化信息，并将其加入上下文以赠强生成内容的可靠性

这样就能提高和大模型沟通的效率

Function Calling: **规定**大模型回答的**格式**，例如**JSON**，方便程序进行解析后调用对应的**功能**

MCP: 模型上下文协议，**规定**工具和上下文如何被标准化地提供给大模型

![image.png](工程师沉淀/AI/3%20AI%20应用开发层/名词/image.png)

工作流：解决固化流程的相似问题中，浪费Token、不规范等问题

LangChain：通过编程的方式实现工作流解决链式任务

低代码平台：通过图形化界面拖拽的方式实现工作流

Skill：Prompt加载器，用于更加灵活的处理场景，将一个大问题中解决所有各类子问题需要用到的 脚本、模版 等等放在一个目录下进行管理，同时该目录有一个 统一的说明文件类似于README 方便大模型知道去哪里能找到对应子问题的解法

SubAgent：用于上下文隔离，防止上下文过长
