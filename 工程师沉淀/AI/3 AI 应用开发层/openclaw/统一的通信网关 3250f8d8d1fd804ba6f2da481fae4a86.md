# 统一的通信网关

网关：用于 消息平台 和 业务程序 的中转层

代理层 + 协议适配层 + 入口层

OpenClaw 用 网关统一控制面+通道插件统一适配面 实现通信的统一

所有第三方App等渠道都被收敛到**同一套协议、路由和出站发送链路**

## 3) 两层如何合起来形成“通信统一”

1. 入站统一路径（以飞书为例）
    
    `event -> monitor -> handleFeishuMessage -> resolveAgentRoute -> dispatchReplyFromConfig -> channel dispatcher -> provider send`
    
    对应：
    
    `extensions/feishu/src/monitor.account.ts:380` -> `extensions/feishu/src/bot.ts:862` -> `1168` -> `1524` -> `extensions/feishu/src/reply-dispatcher.ts:313` -> `extensions/feishu/src/send.ts:278`
    
2. 出站统一路径（任意渠道）
    
    `sendMessage` 先选渠道，再解析 target，再统一投递：
    
    `src/infra/outbound/message.ts:166-247` -> `src/infra/outbound/channel-selection.ts:86-134` -> `src/infra/outbound/targets.ts:171-238` -> `src/infra/outbound/deliver.ts:531-828`。
    
    最终落到对应插件 `outbound.sendText/sendMedia`（如飞书 `extensions/feishu/src/outbound.ts:79-168`）。
    
3. 跨渠道回路由统一
    
    `dispatch-from-config` 在检测到 `OriginatingChannel != currentSurface` 时走 `routeReply`：
    
    `src/auto-reply/reply/dispatch-from-config.ts:211-233`, `257-272`, `516-526`。
    
    `routeReply` 再统一走 outbound delivery：`src/auto-reply/reply/route-reply.ts:72-166`。
    

一句话总结：**控制面统一“入口、协议、鉴权、方法调度、生命周期”；适配面统一“插件契约、渠道差异封装、入站/出站执行”。**

所以新增一个渠道，基本是实现 `ChannelPlugin` 合同，而不是改网关主干逻辑。
