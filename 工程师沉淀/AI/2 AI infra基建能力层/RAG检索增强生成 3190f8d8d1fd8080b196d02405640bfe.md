# RAG检索增强生成

大模型默认只能访问联网数据

如果想要让大模型能基于特殊个性化配置的文档提高输出质量，就需要RAG

RAG的核心思想是将 **经典搜索系统** 和 **大模型的语言推理能力（猜词游戏）** 结合

**由外部检索系统召回相关文档后再喂给**大模型上下文

《提示词工程》

1. **检索**
    
    从外部知识源中找相关信息，可以是
    
    - 向量数据库：一般会将用户的问题转换为向量进行**语义匹配**，而不是字面匹配
        
        [为什么RAG中通常用向量数据库](为什么RAG中通常用向量数据库%203250f8d8d1fd80088f0cc72fe9b4b0e4.md)
        
    - 搜索引擎
    - 知识库
    - API
2. **生成**
    
    将检索到的内容连同用户问题一起喂入大模型的**上下文**中

# RAG架构

![image.png](工程师沉淀/AI/2%20AI%20infra基建能力层/RAG检索增强生成/image%201.png)

## 组件

1. 检索器：管理知识库
    
    [检索器](检索器%203250f8d8d1fd80d6aa66c86d220cf4d4.md)
    
    负责检索当前问题大模型需要的相关内容，使得大模型能获取更多信息，降低了幻觉和误导性回复的可能性
    
    例如 向量数据库
    

当输入要求时，先由检索器去知识库搜索召回提示词相关的文档，然后系统创建增强提示词，把相关文档信息加入到原始提示词中

## 限制

更多的信息插入不一定好，主要是受到大模型**上下文**的限制

[大模型的上下文限制主要是因为 Transformer 架构需要对每个词料做注意力计算，过长会导致计算代价提高，并且位置编码也很大](index%2032b0f8d8d1fd80cf8c83d12aed12c59a.md) 

所以检索器需要**筛选**文档
