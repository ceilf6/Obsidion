# AI分层系统

[美团内部分层](AI%E5%88%86%E5%B1%82%E7%B3%BB%E7%BB%9F/%E7%BE%8E%E5%9B%A2%E5%86%85%E9%83%A8%E5%88%86%E5%B1%82%203300f8d8d1fd809594f9c68707bc01c4.md)

简单来说：

**Memory、RAG 这些 AI infra 一般不属于 LLM 模型基层，而属于应用层 / LLM 系统层（LLM Application Infrastructure）。**

但它们的位置其实在 **“模型之上、应用之下” 的中间层**，通常叫：

- **LLM Infrastructure**
- **AI Infra**
- **LLM System Layer**
- **Agent Infra**

下面我从 **三层架构**给你讲清楚。

---

# **一、LLM 技术栈分层**

一个完整 AI 系统一般分为 **三层**：

```
AI Application Layer
        ↑
LLM Infrastructure Layer
        ↑
Foundation Model Layer
```

### **1️⃣ Foundation Model Layer（模型基层）**

这一层就是 **真正的大模型本体**。

典型组件：

- LLM
- Tokenizer
- Embedding model
- 推理引擎
- GPU inference runtime

典型系统：

- GPT
- Claude
- Llama
- DeepSeek
- Qwen

技术组件：

- Transformer
- attention
- KV cache
- tokenizer
- sampling
- inference engine (vLLM / TensorRT-LLM)

这一层的能力只有：

```
输入 token → 生成 token
```

模型 **没有 memory、没有知识库、没有工具能力**。

---

# **二、LLM Infrastructure Layer（AI Infra）**

这一层就是你说的 **AI Infra**。

它解决的问题：

> 如何让一个只会预测 token 的模型变成一个真正可用的 AI 系统。
> 

典型组件：

### **1️⃣ RAG（Retrieval Augmented Generation）**

解决：

```
模型知识过期
上下文长度有限
```

流程：

```
用户问题
   ↓
embedding
   ↓
向量数据库检索
   ↓
拼接到 prompt
   ↓
LLM
```

常见组件：

- embedding model
- vector database
- retrieval pipeline

典型数据库：

- Pinecone
- Weaviate
- Milvus
- Chroma
- pgvector

---

### **2️⃣ Memory（Agent Memory）**

解决：

```
LLM 无法长期记忆
```

Memory类型：

**Short-term memory**

```
chat history
session context
```

**Long-term memory**

```
vector memory
episodic memory
semantic memory
```

实现方式：

```
Conversation → embedding → vector DB
```

或者

```
key-value store
```

---

### **3️⃣ Tool / Function Calling**

解决：

```
LLM不能执行真实操作
```

例如：

```
LLM → 调用API
LLM → 调数据库
LLM → 调浏览器
LLM → 调代码执行
```

框架：

- OpenAI function calling
- MCP
- LangChain tools
- Toolformer

---

### **4️⃣ Agent Framework**

解决：

```
任务规划 + 工具使用
```

例如：

```
task planning
reasoning
tool execution
loop
```

框架：

- LangGraph
- AutoGPT
- CrewAI
- AgentScope
- OpenAI Agents

---

# **三、Application Layer（应用层）**

这一层才是真正的 **产品应用**。

例如：

- ChatGPT
- Cursor
- Devin
- Perplexity
- AI IDE
- AI客服
- AI coding agent

你的项目 **FrontAgent** 就属于这一层。

但它依赖：

```
FrontAgent
   ↓
Agent framework
   ↓
RAG / Memory / Tools
   ↓
LLM
```

---

# **四、完整架构图**

完整 AI 系统：

```
                AI Application
       (ChatGPT / Cursor / Agents)
                        │
                        │
                Agent Framework
            (LangGraph / CrewAI)
                        │
                        │
        ┌──────── AI Infrastructure ────────┐
        │                                   │
        │   RAG        Memory       Tools   │
        │   Vector DB  Chat Memory  API     │
        │                                   │
        └───────────────────────────────────┘
                        │
                        │
              Foundation Model Layer
        (GPT / Claude / Llama / DeepSeek)
```

---

# **五、为什么很多人叫它 AI Infra**

因为这些组件是：

**所有 AI 应用都必须依赖的基础设施**

类似于 Web：

```
Web Application
      ↑
Web Framework (Next.js)
      ↑
Infrastructure
(Databases / Cache / Message Queue)
      ↑
OS / Hardware
```

AI 也类似：

```
AI Application
      ↑
Agent Framework
      ↑
AI Infra
(RAG / Memory / Tool / VectorDB)
      ↑
Foundation Model
```

---

# **六、为什么你现在看到很多人做 AI Infra**

因为：

**应用 ≈ 1000个**

但

**Infra ≈ 10个**

所以 Infra 是更高杠杆的方向。

典型公司：

- LangChain
- LlamaIndex
- Pinecone
- Weaviate
- vLLM
- TogetherAI

---

# **七、MCP 在这个体系中的位置**

你刚刚问的 MCP，其实也属于：

**AI Infra（Tool Infrastructure）**

作用：

```
Agent
   ↓
MCP
   ↓
External Tools
```

例如：

```
LLM
 ↓
Agent
 ↓
MCP
 ↓
Browser / Filesystem / Git / Slack
```

所以：

```
MCP = Tool infrastructure
```

---

# **八、总结**

Memory / RAG 属于：

```
❌ 不是 LLM 模型层
❌ 不是应用层

✅ AI Infrastructure 层
```

位置：

```
Application
   ↑
AI Infra
(RAG / Memory / Tools / Agent)
   ↑
Foundation Model
```
