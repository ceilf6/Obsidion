# 执行上下文 - 词法环境 作用域链 闭包

ES6前

```jsx
ExecutionContext (ES5)
├─ ThisBinding          ← this 指向
├─ VariableObject (VO)  ← 存 var 声明、函数声明、函数参数
└─ ScopeChain           ← [[scope]] 链，用于变量查找
```

**作用域链**在 ES5 里是独立的字段，不是从 变量对象VariableObject 派生出来的

ES6

```jsx
ExecutionContext (ES6+)
├─ ThisBinding          ← **this** 指向
├─ LexicalEnvironment   ← 当前作用域的**词法环境**
│   ├─ Environment Record  ← 实际存储 **let/const/函数**声明
│   └─ outer            ← 指向外层词法环境 ← 这才是**作用域链**
└─ VariableEnvironment  ← **变量环境** - 专门存 **var** 声明、用于区分 var 的提升
```

执行上下文既 **存储** 运行时数据，也 **包含** 作用域链，通过链式连接的多个执行上下文共同构成了变量的可见范围。

# VariableEnvironment 变量环境

## var 没有块级作用域

### 块级作用域 - var穿透

https://github.com/ceilf6/Lab/commit/2943b794cd2a1f467f1b5619f84e09882438b79b

```jsx
/*
JS/engine-source/src/common/globals.h 中
VariableMode 标记实现: 进入块级作用域时压入新 Context（仅含 kLet/kConst 变量），kVar 变量在编译期就被提升到函数级 Context slot，运行时根本不需要第二条链
*/

if (true) {
    var name = 'ceilf6'; // 写入函数级 VariableEnvironment
    let age = 20; // 写入块级 LexicalEnvironment
}
console.log(name); // logs 'ceilf6'
console.log(age); // let 无法穿透
```

**进入 { } 块级作用域时，只创建新的词法环境 、不创建变量环境**，
而 let和const声明的变量是存储在词法环境 ，var声明的是存储在变量环境

所以

- **var** 就能**穿透块**
- 而 **let, const** 就是**块级**作用域

```jsx
  // var 声明被提升到函数作用域 => 穿透机制
  if (mode == VariableMode::kVar && !is_declaration_scope()) {
    // 当前作用域是块级（if/for/{}），但 var 声明不属于这里
    // → 自动跳转到最近的函数/脚本作用域去声明
    return GetDeclarationScope()->DeclareVariable(
        declaration, name, pos, mode, kind, init, was_added,
        sloppy_mode_block_scope_function_redefinition, ok);
  }
```

### 只有函数作用域

```jsx
for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 0)
}
```

由于var是存在变量环境中，没有块级作用域，只有函数作用域，所以上面代码等价于

```jsx
var i

for (i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 0)
}
```

又由于 setTimeout 创造了计时器任务到计时器线程中，会等 JS 把循环执行完之后，输出都是 闭包引用的同一个i 即最后的3

即使用的 .then(() => console.log(i)) 微任务也全都是3

1. 用 let
2. IIFE 创建函数作用域
    
    ```jsx
    for (var i = 0; i < 3; i++) {
        (function (i) {
            setTimeout(() => {console.log(i)}, 0)
        })(i)
    }
    ```

# LexicalEnvironment 词法环境

## 作用域链

1. **编译**期：**Scope**树 - **静态**
    
    ```jsx
    scopes.h 中的 Scope::outer_scope_
      ScriptScope
      └─ FunctionScope (fn)
          └─ BlockScope ({ let y })
    ```
    
    这是 AST 里的**静态**结构，描述**代码的词法嵌套关系**，编译完就**固定**了，不随调用变化
    
2. **运行**时：**Context 链 - 动态**
    
    ```jsx
    Context::PREVIOUS_INDEX 指针
      NativeContext（全局）
      └─ FunctionContext（fn 被调用时创建）
          └─ BlockContext（{ } 被执行时创建）
    ```
    
    这是堆上的对象链，**每次函数调用都创建新的**，**是 Scope 树的运行时实例化**
    

```jsx
Scope 树（1份，编译期）         Context 链（N份，每次调用）
─────────────────────────────────────────────────────────
FunctionScope ──实例化为──→ FunctionContext（调用1次）
                         → FunctionContext（调用2次）  ← 闭包/递归各自独立
BlockScope    ──实例化为──→ BlockContext（每次执行该块）
```

**同一个函数被调用 N 次，Scope 只有 1 份，但 Context 有 N 份**——这正是**闭包**能**各自独立保存变量的根本原因**

```jsx
  // 把"编译期 Scope 树距离"转换成"运行时 Context 链跳转深度"的桥梁
  int ContextChainDepth(Scope* scope) {
    return scope_->ContextChainLength(scope); // **编译期算好深度** → 运行时用 depth 跳链
  }
```

### 调用栈 与 作用域链

调用栈管理的是**运行顺序**，首先有一个全局执行上下文在栈底，执行到哪个区域块就会入栈一个当前执行上下文

作用域链维护的是**变量可见性**，由**词法嵌套**（源码写法）决定，在编译期就固定了

⇒ 闭包 - 让变量的生命周期独立于调用栈

[**假如作用域链也在栈上，闭包就无法实现。**](%E6%89%A7%E8%A1%8C%E4%B8%8A%E4%B8%8B%E6%96%87%20-%20%E8%AF%8D%E6%B3%95%E7%8E%AF%E5%A2%83%20%E4%BD%9C%E7%94%A8%E5%9F%9F%E9%93%BE%20%E9%97%AD%E5%8C%85%203120f8d8d1fd8022b3eaee14fa65b4b3.md) 

### 闭包

```jsx
function outer() {
  let x = 1;
  return function inner() {
    return x;  // outer 已经返回了，栈帧已销毁，x 还在哪里？
  }
}
```

当外部块级作用域嵌套内部块级作用域的情况下，在退出一个 outer外部块级作用域 时，它的**栈帧**被弹出销毁。但 inner内部块级作用域 还持有对 外部块级作用域中变量`x` 的引用。

**假如作用域链也在栈上，闭包就无法实现。**

正是作用域链不在栈上，所以在 V8 中，将需要被捕获的变量从**栈提升到堆**( 逃逸 )，存在 **`Context` 对象**里。

在编译期分析得到其词法环境被引用 ⇒ 原先存储在栈上的变量提升到了堆上，让变量的生命周期独立于调用栈 从栈中逃逸、延缓了被垃圾回收

[**同一个函数被调用 N 次，Scope 只有 1 份，但 Context 有 N 份**——这正是**闭包**能**各自独立保存变量的根本原因**](%E6%89%A7%E8%A1%8C%E4%B8%8A%E4%B8%8B%E6%96%87%20-%20%E8%AF%8D%E6%B3%95%E7%8E%AF%E5%A2%83%20%E4%BD%9C%E7%94%A8%E5%9F%9F%E9%93%BE%20%E9%97%AD%E5%8C%85%203120f8d8d1fd8022b3eaee14fa65b4b3.md) 

## 1. **编译期 — 决定哪些变量需要进 Context**

https://github.com/ceilf6/Lab/commit/ad920ab4546cfb5db033f237063ebab663cbccf4

```jsx
	// 作用域是否需要一个运行时 Context 对象（= 是否需要词法环境）
  bool NeedsContext() const {
    // Catch scopes always have heap slots.
    DCHECK_IMPLIES(is_catch_scope(), num_heap_slots() > 0);
    DCHECK_IMPLIES(is_with_scope(), num_heap_slots() > 0);
    DCHECK_IMPLIES(ForceContextForLanguageMode(), num_heap_slots() > 0);
    return num_heap_slots() > 0;
    // num_heap_slots > 0 → 有变量需要分配在堆上（被闭包捕获/块级let/const）
  }
```

`with` / `catch` 作用域永远需要；函数和块级作用域只有存在**堆变量**时才需要。没有闭包、没有 `let/const` 的普通块 `{}` 直接跳过，不创建 Context

## 3. 运行时 Context 链 — ContextScope 管理 outer 引用

https://github.com/ceilf6/Lab/commit/2d4ff28dc5a100d1c7d8cf8f0e49f97306c326d0

**ContextScope** 类是词法环境链的 资源**管理器**

RAII: 在对象构造时获取资源, 在对象析构时释放资源

每次 **ContextScope** 构造函数 → 链延长；~析构 → 链缩短，块执行完自动回收。

**outer_ 指针实现链式记录外层 Context**

```jsx
class V8_NODISCARD BytecodeGenerator::ContextScope {
 public:
  ContextScope(BytecodeGenerator* generator, Scope* scope,
               Register outer_context_reg = Register())
      : generator_(generator),
        scope_(scope),
        outer_(generator_->execution_context()), // 记录外层 Context
        // outer_ 指针 = 规范 outer reference = 作用域链
        register_(Register::current_context()),
        depth_(0) {
    DCHECK(scope->NeedsContext() || outer_ == nullptr);
    if (outer_) {
      depth_ = outer_->depth_ + 1; // 链深度 +1

      // Push the outer context into a new context register.
      if (!outer_context_reg.is_valid()) {
        outer_context_reg = generator_->register_allocator()->NewRegister();
      }
      outer_->set_register(outer_context_reg); 
      generator_->builder()->PushContext(outer_context_reg); // 旧 Context 入寄存器
    }
    generator_->set_execution_context(this); // 当前 Context = 新建的这个
  }

  ~ContextScope() {
    if (outer_) {
      DCHECK_EQ(register_.index(), Register::current_context().index());
      generator_->builder()->PopContext(outer_->reg()); // 恢复外层 Context
      outer_->set_register(register_);
    }
    generator_->set_execution_context(outer_);
  }

```

## 4. 变量读取 — 沿 Context 链查找

https://github.com/ceilf6/Lab/commit/25641cb0784053ea41c369730715e1a4dac53804

```jsx
    case VariableLocation::CONTEXT: {
      // 计算目标变量在 Context 链上的深度
      int depth = execution_context()->ContextChainDepth(variable->scope());
      ContextScope* context = execution_context()->Previous(depth); // 沿链向上找
      Register context_reg;
      if (context) {
        context_reg = context->reg();
        depth = 0;
      } else {
        context_reg = execution_context()->reg();
      }

      bool is_immutable = variable->maybe_assigned() == kNotAssigned;
      Register acc = Register::virtual_accumulator();
      if (is_immutable && IsVariableInRegister(variable, acc)) {
        return;
      }

      // 生成 LoadContextSlot 字节码，附带链深度 depth
      builder()->LoadContextSlot(context_reg, variable, depth);
      // let/const 还需要 TDZ 检查
      if (VariableNeedsHoleCheckInCurrentBlock(variable, hole_check_mode)) {
        BuildThrowIfHole(variable); // → ThrowReferenceErrorIfHole
      }
      if (is_immutable) {
        SetVariableInRegister(variable, acc);
      }
      break;
    }
```

规范作用域链查找 outer reference **逐级向上**: 

ContextChainDepth **计算"要向上跳几层 outer"**，字节码 `LoadContextSlot` 在运行时**根据这个深度遍历 `Context.PREVIOUS_INDEX` 指针链**

```jsx
源码: 
function fn() { 
	let x = 1; 
	{ 
		let y = 2; 
		console.log(x, y) 
	} 
}
                                                                      
编译期 (scopes.cc)
  fn 的 FUNCTION_SCOPE  → num_heap_slots > 0 (x 被块内闭包可见) → NeedsContext ✓
  块级 BLOCK_SCOPE      → num_heap_slots > 0 (y 是 let)          → NeedsContext ✓

字节码生成 (bytecode-generator.cc)
  进入 fn:
    BuildNewLocalActivationContext()   → CreateFunctionContext [x: hole]
    ContextScope fnCtx(this, fnScope)  → execution_context = fnCtx

  进入 { }:
    BuildNewLocalBlockContext(scope)   → CreateBlockContext [y: hole]
    ContextScope blockCtx(this, blkScope)
      → PushContext(fnCtx寄存器)       ← 保存外层
      → execution_context = blockCtx  ← 当前链顶

  读取 x (CONTEXT, depth=1):
    LoadContextSlot blockCtx.reg, x, depth=1
      → 运行时沿 PREVIOUS_INDEX 向上跳 1 层 → fnCtx → 读出 x

  读取 y (CONTEXT, depth=0):
    LoadContextSlot blockCtx.reg, y, depth=0 → 直接在当前 Context 读

  块结束:
    ~ContextScope() → PopContext → execution_context = fnCtx  ← 链缩短
    blockCtx 销毁, [y: ...] 不可达
```
