# 视觉格式化模型（布局规则）

盒模型：规定单个盒子的规则

视觉格式化模型（布局规则）：页面中**多个盒子**排列规则

视觉格式化模型，大体上将页面中**盒子的排布分为三种方式**

1. 常规流
2. 浮动
3. 绝对定位

# 一. 常规流布局

常规流、文档流、常规文档流、普通文档流

所有元素，默认情况下，都属于常规流布局

总体规则：**块盒独占一行，行盒水平方向依次排列**

## 包含块（containing block）

每个盒子都有它的包含块，包含块决定了盒子的排列区域（活动区域、坐标系）。

绝大部分情况下：盒子的包含块，为其**父元素的内容盒**

## 块盒

### 1. 每个块盒的**总宽度**，必须恰好**等于包含块的总宽度**

width 的默认值是 auto : 将剩余空间吸收掉

margin的默认值是0，其取值也可以为 auto 来吸收。当两个都是auto时margin抢不过 width

若 宽度、边框、内边距、外边距 计算后仍然有剩余空间，该剩余空间被 margin-right 全部吸收

在常规流中，块盒在其包含块中**居中**：

**定宽**，然后 **左右margin设为 auto 吸收**

```html
margin-left: auto;
margin-right: auto;
```

当margin宽度为负数时，相当于能吸收的剩余空间变大

### 2. 每个块盒垂直方向上的 auto 值

height: auto 适应内容的高度

margin: auto 表示 0

### **3. 百分比**取值

1) padding、width、margin 可以取值为百分比

以上的所有百分比**相对于包含块**的**宽度**

注意是宽度，margin-top, padding-top 等即使是垂直方向也是取的包含块的宽度计算百分比

2) height 的百分比

包含块的宽度取决于子元素的高度时（适应时），子元素设置百分比无效

包含块的高度不取决于子元素高度时，子元素百分比相对于父元素高度

### 4. 上下**外边距的合并**

两个常规流块盒，上下外边距**相邻**时（即没有内外**边距**，没有行盒、**清除浮动**等分隔、父元素没有创建**BFC**），那么两个块盒外边距会合并：

二者相等等于**较大者**

解决

1. 用**内边距** - 用父元素的 padding-top
2. 给父元素创建 **BFC**（如overflow: hidden）

# 二. 浮动

## 应用场景

1. 文字环绕
2. 横向排列

## 产生方式

修改 float 属性值为:

1. left: 左浮动，元素**在包含块中靠上靠左**排列
2. right: 右浮动，元素在包含块中靠上靠右排列

默认值是 none ，即常规流

## 浮动的基本特点

1. 当一个元素浮动后，元素类型必定为**块盒**
2. 浮动元素的**包含块**，和常规流一样，为**父元素的内容盒**

### 盒子尺寸

1. width 为 auto 时，适应内容宽度
2. height 为 auto 时，与常规流一致，适应内容的高度（高度的 auto 无论什么情况都是适应内容高度）
3. margin 为 auto 时为 0，没有吸收剩余空间的说法
4. 边框、内边距、百分比设置与常规流一样

### 盒子排列

1. 左浮动的盒子靠上靠左
2. 右浮动的盒子靠上靠右
3. **浮动盒子**在包含块中排列时，会**避开常规流块盒**
4. **常规流块盒**在排列时，**无视浮动盒子**
5. **行盒**在排列时，会**避开浮动盒子** - 文字环绕只需要开启浮动即可
    
    “ **行盒 < 浮动盒 < 常规流块盒** “
    
    ```
    由于是块盒，所以是从该块盒最左侧开始的，也就是图片左边缘，
    所以如果想要让文字开头和图片有间距得用图片的外边距而不是文字行盒的外边距
    ```
    
6. 外边距合并不会发生，**外边距合并只会在常规流中发生**

> 如果文字没有在行盒中，浏览器会自动生成一个行盒包裹文字（span）该行盒叫做匿名行盒
> 

## 高度坍塌

### 原因

高度坍塌的根源是因为**常规流块盒会无视浮动盒子**，导致常规流盒子的自动高度在计算时不会考虑浮动盒子

### 解决方案

### 1. 清除浮动

涉及 clear 这个 css 属性

1. 默认值 none
2. left: 清除左浮动，该元素必须出现在前面所有左浮动盒子的下方
3. right: 清除右浮动，该元素必须出现在前面所有右浮动盒子的下方
4. both: 清除左、右浮动，该元素必须出现在前面所有浮动盒子的下方

那么

1. 只需要设置一个元素在浮动元素后面

```html
< > float htmls
<div class="clearfix">
```

然后设置 clear

```html
.clearfix {
	clear: both;
}
```

1. 但是这样需要设置一个新元素，可以直接在**浮动元素父元素**中设置**伪元素**

```html
<div class="father-of-float clearfix">

.clearfix::after {
    content: "";
    display: **block**;
    **clear**: both;
}
```

### 2. 创建BFC

利用 “**创建 BFC 的元素，其自动高度需要计算浮动元素**”

所以创建 BFC 即可

1. position: absolute;
2. float: left;

上面两种方式会影响盒子布局，所以一般是选择副作用最小的

1. **overflow: hidden**;

（但是相较之下，clear清除浮动才是副作用最小的）

## 浮动元素父元素都得 clearfix 或 BFC

虽然可能现在没有问题，但是页面中可能已经存在高度为 0 的元素，所以给每个浮动元素父元素都清除浮动才是最稳的

# 三. 定位

手动控制元素在包含块中的**精准**位置

涉及的 CSS 属性：position

## position属性

1. 默认值：static 静态定位，即不定位
2. relative ：相对定位
3. absolute ：绝对定位
4. fixed ：固定定位

一个元素，**只要 position 的取值不是 static ，认为该元素是一个定位元素**

定位元素会**脱离文档流，相对定位除外**

一个脱离了文档流的元素特点

1. 文档流中的元素摆放时，会**忽略**脱离了文档流的元素
2. 文档流中元素计算自动高度时，会忽略脱离了文档流的元素

## 相对定位 relative

不会导致元素脱离文档流，只是让元素**在原来位置上进行偏移**

可以通过四个CSS属性对相对定位元素设置距离盒子四条边的偏移量

1. left
2. right
3. top
4. bottom

> 通过 margin-left 修改的话可能会影响盒子 content 的大小，如果通过相对定位的话不会影响盒子（并且任何盒子都不会影响）
> 

盒子的偏移不会对其他盒子造成任何影响

当 左右 / 上下 冲突时，以 左 上 为准

## 绝对定位 absolute

1. 宽高为 auto ，适应内容
2. 包含块（坐标系）变化：找祖先元素（从父元素开始往上）中第一个**定位元素**，该元素的**填充盒（内容+内边距）为其包含块**。若找不到，则其包含块为**整个网页（初始化包含块）**

仍然是 left, right, top, bottom 设置距离 包含块四条边 的偏移量

例如一个小标识需要在另一个元素内部，那么一般将**目标坐标系元素设置 position: relative** 开启定位元素 成为包含块，然后 小标识开启 绝对定位

## 固定定位 fixed

其他情况和绝对定位完全一样

唯一不同 - 包含块不同：固定定位的包含块固定为**视口**

> 视口：固定定位元素相对于视口是固定的

初始化包含块 - 网页：绝对定位元素是相对于整个网页的，也就是说移动滚动条时绝对定位元素相对于视口会移动
> 

## 定位下的居中

某个方向上的居中：

1. 水平方向定宽（垂直方向定高）
2. 将 左右（上下）距离设置为 **0**
3. 将 左右（上下） **margin 设置为 auto**

在绝对定位和固定定位中，**margin 为 auto 且 宽高固定 时，会自动吸收剩余空间**

## 多个定位元素重叠时

堆叠上下文

设置 z-index ：通常情况下，该值越大，越靠近用户

**只有定位元素设置 z-index 有效**

z-index 可以为负数， 那么该定位元素遇到 常规流、浮动元素 其会被覆盖

## 绝对定位、固定定位元素一定是块盒，一定不是浮动

没有外边距合并
