# 浏览器页面处理流程

url 本质就是一次对资源的请求以及对资源的解析处理

处理 → 网络 → 渲染

对应进程是

浏览器主进程 → 网络进程 → 渲染进程的渲染主线程

请求行（请求方式 url） → 请求头 → 响应行 → 响应头 → 响应体 → 解析响应体：渲染过程

首先 处理 在 **浏览器主进程** 处理

1. 浏览器自动**补全**协议、端口
2. 浏览器自动完成url**编码**，确保没有非ASCII码
3. 浏览器**根据url地址判断是否命中浏览器缓存**，如果命中了就直接不发送请求
    
    [缓存读取规则](../%E6%B5%8F%E8%A7%88%E5%99%A8/%E5%AE%A2%E6%88%B7%E7%AB%AF%E7%BC%93%E5%AD%98%20%E6%B5%8F%E8%A7%88%E5%99%A8%E7%BC%93%E5%AD%98%20%E7%A1%AC%E7%9B%98%E7%BC%93%E5%AD%98%20HTTP%E7%BC%93%E5%AD%98%202f90f8d8d1fd80c98afbf4e6af8ea58a.md) 
    

网络相关 在 **网络进程** 处理

1. 通过 **DNS（应用层）** 解析找到**服务器**的**IP地址**
    
    [域名 DNS](%E5%9F%9F%E5%90%8D%20DNS%203000f8d8d1fd8005921cea5b6f2e7cfb.md) 
    
2. **浏览器向服务器**发出建立 **TCP（传输层）** 连接的申请，完成三次握手后，连接通道建立
3. 先决定使用HTTP还是HTTPS，若使用了**HTTPS**协议，则还会进行**SSL握手**，建立加密信道
    
    然后在连接过程中协商HTTP的版本
    
4. **浏览器决定**要附带哪些 **cookie** 到**请求头**中
    
    [浏览器决定携带cookie过程](cookie/%E6%B5%8F%E8%A7%88%E5%99%A8%E5%86%B3%E5%AE%9A%E6%90%BA%E5%B8%A6cookie%E8%BF%87%E7%A8%8B%203170f8d8d1fd80e59f06fe683c6a5d54.md) 
    
    像 Secure 的 cookie 只在**HTTPS**中携带；看是否过期（Expires / Max-Age）；
    
5. 浏览器自动设置好请求行（协议版本）、请求头（cookie），发出**GET请求**
6. 服务器处理请求，进入后端处理流程。完成处理后，服务器**响应**一个HTTP报文给浏览器。
7. 浏览器根据使用的**协议**版本，以及 **Connection 是否为 keep alive** ，决定是否要 **保留TCP**连接。
8. 浏览器根据响应行中的**响应状态码**决定如何处理这一次响应
9. 浏览器根据响应头中的**Content-Type**字段识别响应类型并对响应体做对应处理
10. 浏览器根据**响应头**的其他内容(强制缓存Cache-Control: max-age , Expires; 协商缓存Etag, Last-Modified)完成**缓存**、(set-cookie)**cookie**的设置

解析、渲染相关 是在 **渲染进程的渲染主线程** 中

1. 浏览器开始从上到下**解析**HTML，若遇到外部资源链接，则进一步请求资源
    
    HTML 解析是流式的，不会等所有下载完再解析，而是边下载边解析
    
2. 解析过程中生成DOM树、CSSOM树，然后一边生成，一边把二者合并为渲染树（rendering tree），随后对渲染树中的每个节点计算位置和大小（reflow）得到布局树，最后把每个节点利用GPU绘制到屏幕（repaint）…
    
    [浏览器渲染流程](../%E6%B5%8F%E8%A7%88%E5%99%A8/%E6%B5%8F%E8%A7%88%E5%99%A8%E6%B8%B2%E6%9F%93%E6%B5%81%E7%A8%8B%202f70f8d8d1fd80d5a582c918abb221ef.md) 
    
3. 在解析过程中还会触发一系列的事件，当DOM树完成后会触发DOMContentLoaded事件，当所有资源加载完毕后会触发load事件…

浏览器识别 

## Content-type

为

### 1. text/html

（例如 a 元素）

后知道这是一个页面，就会丢弃旧页面，开始解析这个 html 文档

**link 元素** →  如果是相对路径，那么先转换为绝对路径拿到url地址 → 新的请求这个url地址

> 相对路径相对的是当前页面的url地址目录

绝对路径：完整的url地址
可以省略协议用页面的协议 //a.ceilf6.com:443/hello/world
> 
> 
> 协议、主机、端口都省略
> /hello/world
> 

**img 元素** → 不立马请求 img 的 url ，而是继续解析 HTML 文档 → 等后面拿到后再应用到布局中

**script 元素** → 会阻塞解析、立马请求该脚本资源的url → 响应拿到类型是 application/javascript → 需要等待JS执行完毕

（浏览器不会看请求的文件后缀 .js ，只认 Content-type）

### 2. text/css

解析并应用CSS样式

### 3. application/javascript

阻塞解析，需要等待JS执行完毕
