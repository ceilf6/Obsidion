# 源码解析

你这里的 “CMJ” 我按 **CJS / CommonJS** 理解。基于这个 Node 源码仓库，`require` 的主链路可以概括成：

`模块内的 require` -> `Module.prototype.require` -> `Module._load` -> `解析路径` -> `查缓存/处理循环依赖` -> `module.load` -> `按扩展名加载` -> `._compile` -> 返回 `module.exports`

**1. `require` 不是全局魔法，它是“按模块生成的闭包”**

在 `makeRequireFunction(mod)` 里，Node 为每个 CommonJS 模块生成自己的 `require`：

[lib/internal/modules/helpers.js](https://www.notion.so/Users/a86198/Desktop/Lab/NodeJS/Node-source/lib/internal/modules/helpers.js#L183)

这里最关键的一句其实是：

- `function require(path) { return mod.require(path); }`

也就是说，模块里拿到的 `require`，本质上只是当前 `Module` 实例的一个包装函数。

同时它还挂了几个常见属性：

- `require.resolve`
- `require.cache`
- `require.extensions`
- `require.main`

所以你在业务代码里用到的 `require.cache`，底层就是 `Module._cache`。

**2. 真正开始加载的是 `Module.prototype.require()`**

入口很薄：

[lib/internal/modules/cjs/loader.js](https://www.notion.so/Users/a86198/Desktop/Lab/NodeJS/Node-source/lib/internal/modules/cjs/loader.js#L1567)

它只做三件事：

- 校验 `id` 是非空字符串
- `requireDepth++`
- 调 `wrapModuleLoad(id, this, false)`

`wrapModuleLoad()` 主要是给 tracing/hook 留包装，真正干活的是 `Module._load()`。

**3. `Module._load()` 是核心调度器**

这里是整个 `require` 的中枢：

[lib/internal/modules/cjs/loader.js](https://www.notion.so/Users/a86198/Desktop/Lab/NodeJS/Node-source/lib/internal/modules/cjs/loader.js#L1238)

它的关键逻辑是：

- 先看相对路径快速缓存 `relativeResolveCache`
- 再做解析 `resolveForCJSWithHooks(...)`
- 处理内建模块，如 `node:fs` / `fs`
- 查 `Module._cache`
- 如果命中且已加载完，直接返回 `cachedModule.exports`
- 如果命中但还没加载完，说明发生循环依赖，返回“半初始化”的 exports
- 否则新建 `Module(filename, parent)`，并且**先放进缓存，再执行加载**

这一点非常关键：

**Node 是“先缓存、后执行”**，这正是 CommonJS 能处理循环依赖的原因。

循环依赖相关逻辑在这里：

[lib/internal/modules/cjs/loader.js](https://www.notion.so/Users/a86198/Desktop/Lab/NodeJS/Node-source/lib/internal/modules/cjs/loader.js#L1010)

如果循环依赖时访问了还不存在的导出属性，Node 甚至会挂一个 Proxy 来给 warning。

**4. 路径解析分成两层：找搜索路径 + 找具体文件**

先看搜索目录：

[lib/internal/modules/cjs/loader.js](https://www.notion.so/Users/a86198/Desktop/Lab/NodeJS/Node-source/lib/internal/modules/cjs/loader.js#L925)

规则很经典：

- 内建模块：直接返回 `null`
- 裸模块名，如 `require('lodash')`：从 `parent.paths + global modulePaths` 找
- 相对路径，如 `require('./a')`：只从当前模块目录找

再看实际找文件：

[lib/internal/modules/cjs/loader.js](https://www.notion.so/Users/a86198/Desktop/Lab/NodeJS/Node-source/lib/internal/modules/cjs/loader.js#L703)

`Module._findPath()` 会依次尝试：

- 直接当文件找
- 补扩展名找：`.js` / `.json` / `.node` 等
- 当目录找，读 `package.json` 的 `main`
- 再退回 `index.js` / `index.json` / `index.node`

`package.json` 的 `main` 分支在这里：

[lib/internal/modules/cjs/loader.js](https://www.notion.so/Users/a86198/Desktop/Lab/NodeJS/Node-source/lib/internal/modules/cjs/loader.js#L515)

现代 Node 还额外支持：

- `package imports`（`#xxx`）
- `package exports`
- CJS/ESM hooks

所以现在的 `require` 比老版本教程里看到的更复杂。

**5. 找到文件后，`module.load()` 决定怎么加载**

入口：

[lib/internal/modules/cjs/loader.js](https://www.notion.so/Users/a86198/Desktop/Lab/NodeJS/Node-source/lib/internal/modules/cjs/loader.js#L1537)

它会：

- 设置 `module.filename`
- 计算 `module.paths`
- 根据扩展名选择 `Module._extensions[ext]`

对应几个典型分支：

[lib/internal/modules/cjs/loader.js](https://www.notion.so/Users/a86198/Desktop/Lab/NodeJS/Node-source/lib/internal/modules/cjs/loader.js#L1925)

[lib/internal/modules/cjs/loader.js](https://www.notion.so/Users/a86198/Desktop/Lab/NodeJS/Node-source/lib/internal/modules/cjs/loader.js#L1977)

[lib/internal/modules/cjs/loader.js](https://www.notion.so/Users/a86198/Desktop/Lab/NodeJS/Node-source/lib/internal/modules/cjs/loader.js#L1994)

含义分别是：

- `.js` / `.cjs` / `.mjs`：走编译执行
- `.json`：`JSON.parse` 后塞进 `module.exports`
- `.node`：走 `process.dlopen()` 加载原生 addon

**6. CommonJS 的“函数包裹”发生在 `_compile()`**

先看 wrapper 定义：

[lib/internal/modules/cjs/loader.js](https://www.notion.so/Users/a86198/Desktop/Lab/NodeJS/Node-source/lib/internal/modules/cjs/loader.js#L372)

也就是经典的：

```jsx
(function (exports, require, module, __filename, __dirname) {
  // your code
});
```

真正编译执行在：

[lib/internal/modules/cjs/loader.js](https://www.notion.so/Users/a86198/Desktop/Lab/NodeJS/Node-source/lib/internal/modules/cjs/loader.js#L1781)

关键步骤：

- `wrapSafe(...)` / `compileFunctionForCJSLoader(...)` 把源码编译成函数
- 生成当前模块专属的 `require`
- 调用编译后的 wrapper：

```jsx
compiledWrapper.call(exports, exports, require, module, filename, dirname)
```

所以你在 CJS 文件里能直接用：

- `exports`
- `require`
- `module`
- `__filename`
- `__dirname`

并不是 JS 语言自带，而是 Node 包装后作为参数注入进去的。

**7. 这版 Node 里的一个重要现实：`require` 已经不只是纯 CJS 了**

这份源码里能明显看到两类现代能力已经揉进来了：

- CJS hooks：`resolveForCJSWithHooks()`、`loadWithHooks()`
- ESM 兼容：`loadESMFromCJS()`、`ERR_REQUIRE_ESM`

也就是说，今天 Node 的 `require` 仍然以 CommonJS 为核心，但已经带上了：

- builtin 模块特殊处理
- package exports/imports
- ESM 互操作
- 自定义 loader hooks

所以如果你拿老版本 Node 的 `Module._load` 教程来对照，会发现现在源码明显更厚。
